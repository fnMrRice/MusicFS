# 曲目列表页设计

状态：主体为设计草案 v0.5，2026-10-10；2026-10-21 补充人工关联与多来源展开实现约定。分类、筛选等其他草案能力仍以实际接口为准。继承[共享布局](ui-design.md)，遵循[跨端架构](architecture.md)。

## 1. 页面结构

顶部固定工具栏保留返回、曲目列表标题；右侧为纯图标按钮，顺序是设置、换肤、浅色竖线、迷你模式、最小化、最大化、关闭。换肤与迷你模式之间增加间距，名称通过 tooltip 展示。左侧高亮曲目列表；品牌 Banner 与“我的账号”区固定，仅中间导航与歌单整体滚动。“我的”收纳我的收藏、最近播放，“歌单”收纳歌单列表，两个分组可独立展开或收起。底部全宽播放器保持固定。

右侧依次为分类浏览、筛选、操作与排序、曲目表格。表格表头在右侧内容滚动时吸顶；不为每一行或分类区添加独立滚动条。

曲目列表只浏览普通音乐。已归属 ASMR 作品或 CD 抓轨副本的音频，不进入全部曲目、专辑、歌手、流派和文件夹视图；筛选项、数量统计和“播放全部”使用相同范围。与普通音乐共用的歌手、流派或祖先目录继续显示，只统计普通音乐成员。排除依据已确认的作品／副本归属，不猜测目录名、标签或音频格式；普通音乐目录副本仍可显示。ASMR 和 CD 抓轨从作品库对应入口及详情页浏览播放。

## 2. 分类与筛选

| 层级 | 入口 | 行为 |
| --- | --- | --- |
| 分类浏览 | 全部曲目 / 歌手 / 专辑 / 流派 / 文件夹 | 默认全部曲目；其他入口先显示对应分类集合，进入分类后显示曲目与可返回的面包屑 |
| 常用筛选 | 来源、格式、仅收藏、仅可播放 | 来源指用户可访问的 Provider 实例；格式如 FLAC、MP3、AAC、NCM，不以格式推断音质 |
| 更多筛选 | 年份、采样率、码率范围、可用状态 | 浮层中编辑，点击应用后统一生效；提供重置，缺少元数据的项归入未知 |
| 当前列表查找 | 搜索曲名、歌手、专辑 | 只在当前分类及筛选范围内查找；与左侧跨来源的独立搜索页区分 |
| 已生效条件 | 可移除条件标签、清空筛选、结果数 | 条件之间取交集，同一多选条件内取并集；清空筛选保留当前分类，清空查找可单独操作 |

分类浏览不搬动文件，不创建歌单。文件夹仅表达 Server 已授权的文件树，不暴露实际磁盘绝对路径；不具备目录浏览能力的来源不提供该入口。歌手、专辑与流派缺失时可从“未知”分类找到曲目。

分类与各筛选项均为目标设计，当前支持范围须由 Server 的实际能力决定；不支持的入口不伪装成可用。

## 3. 排序与列表

操作栏左侧为“播放全部”“加入队列”，右侧为排序字段与独立的升降序按钮；不设“批量选择”入口，每行左侧直接显示复选框。排序下拉包含最近添加、曲名、歌手、专辑、时长；默认最近添加、降序。点击可排序表头切换该字段及方向，与下拉状态保持一致。专辑视图可提供碟号、曲序排序；未知曲序排在末尾。

排序针对整个筛选结果，不只重排已返回的条目。相同排序值使用稳定身份作为末级顺序；追加请求沿用同一音乐库修订。切换分类、筛选或排序时清空旧游标，从首批结果重新获取并回到顶部，忽略旧请求结果；播放队列不随页面重排自动变化。

| 列 | 展示与操作 |
| --- | --- |
| 选择 / 序号 | 最左列常驻复选框，表头提供全选当前已返回条目的复选框并用 tooltip 说明范围，部分选中时显示中间态；后接序号，正在播放行用播放状态图标辅助标识 |
| 曲名 | 小封面、曲名；Live、Remix 等版本信息不能省略为相同歌曲 |
| 歌手、专辑 | 文本过长省略，悬停或键盘聚焦可查看完整信息；可进入对应分类 |
| 来源 | 用户可读的来源名称；已人工关联为同一 Recording 的曲目聚合为一行，可展开全部版本与来源；同名曲目不直接合并 |
| 格式、时长 | 未知值显示“—”；不把 FLAC 等格式标成已验证的高音质 |
| 操作 | 收藏、更多；行悬停或聚焦显示播放按钮，触屏仍有可点击入口 |

不可播放行保留显示并标明原因，例如“来源离线”“需要登录”；启用仅可播放后排除这些行。状态不能仅靠文字颜色区分。当前播放行的突出状态由具体来源曲目身份决定，不按曲名匹配。

## 4. 播放、批量与行菜单

“播放全部”按当前筛选与排序建立队列；“加入队列”追加对应结果。不可播放项跳过并汇总提示；空结果时禁用。大结果集的完整队列构建需要后端支持，不得将仅加载部分当作全部成功。

勾选任一行后，操作栏显示已选数量、加入队列、添加到歌单、收藏、取消选择；取消全部选择恢复普通操作栏，复选框始终显示。点击复选框只切换选择，不触发播放或进入详情。表头全选只选择点击时已返回的条目，不自动选中新追加的条目；若有新条目追加则全选框变为部分选中。自动追加保留已有选择；变更分类、筛选、排序时清空选择并提示。若未来提供全部结果选择，必须另行明确范围和数量。

人工关联入口为操作栏中的「合并歌曲」：勾选至少两条歌曲后可确认关联。已聚合行代表其完整来源集合，确认界面需明确包含的来源，不只取代表曲目。操作由 Server 自身提供，自动重复识别插件关闭时仍可用；修订冲突需刷新后重新判断，不覆盖其他已完成的人工决定。

关联后主列表显示一行，通过展开按钮在下方显示各来源与版本，可单独播放、查看格式和时长、解除关联。原始文件及来源不删除。Server 在分页前完成分组，因此同组来源不会因为分散在不同分页而漏掉。重复识别候选用于辅助人工选择，不直接触发合并。

曲目更多菜单及右键菜单提供立即播放、下一首播放、加入队列、添加到歌单、收藏/取消收藏、曲目详情；不可用操作说明原因。首轮不放永久删除文件操作。

## 5. 状态与实现边界

- 正在加载：保留筛选和排序状态，显示表格骨架；请求失败：错误说明与重试，不误报为空结果。
- 音乐库为空：提示先配置可访问来源；筛选无结果：提供清空筛选及查找入口。
- 动态加载：不显示分页器、已加载数量、每页条数或加载更多按钮。右侧滚动接近列表底部时，通过服务端返回的下一游标自动请求并追加；一次只允许一个追加请求，同一游标不重复请求，按稳定身份消除重复。
- 初次加载用骨架；后续追加期间仅在列表末尾显示小型进度指示与“正在加载…”。失败保留已有列表、滚动位置和选择，在末尾显示“加载失败，重试”；不无限自动重试。确认无下一游标时停止请求，可显示“已经到底了”，不把临时失败视为结束。
- 共同契约仍使用固定修订的游标分页，界面将其呈现为连续滚动。修订失效时提示刷新，不把不同修订的列表拼接；参数变化作废旧请求。追加不跳动滚动位置、不影响当前播放。大量条目可采用虚拟列表，但需保留稳定选中身份与键盘焦点。总数仅在服务端准确返回时展示，不以当前返回数量推算。
- 部分来源离线：展示范围与原因，其余来源仍可浏览；旧数据按过期状态展示。
- 收藏与添加歌单以服务端结果为准，失败保留上下文并允许重试，不静默写回在线平台。
- Server 当前共同契约不能据本稿推断已支持全部分类、过滤、排序、总数与结果集队列；实施前需由 Server 评估 OpenAPI、稳定分页与客户端兼容性，再同步共同契约。

本轮优先确认分类栏、筛选密度、表格列及排序入口；分类集合页与批量模式可在确认后进一步展开。
