# MusicFS 跨端架构设计

状态：共同架构 v0.9，2026-11-14。本文定义 Server 与桌面 Client、Web、Android 之间共同遵守的职责边界、数据语义、协议和协作流程。Android 已有采用 Kotlin、Compose 与 Media3 的本地工程，设备验收另行记录。Server 官方内置插件统一在主进程执行。桌面 Client 同进程原生动态库和 CMake/C++23 约定仍属待实施设计。当前交付及平台限制见[实施总览](implementation.md)和各实现仓库的验证记录；NFS/SMB 仍为待实现设计；Bilibili 已进入匿名公开内容接入阶段，范围见 [Bilibili 来源](../server/docs/providers/bilibili.md)。

Local Files 的实际音乐目录、扫描默认值与监听设置由管理员接口维护，持久化到 Server 托管的插件配置数据库。未显式配置目录权限时，默认允许当前 Server 运行用户的 Music 目录，并兼容旧 YAML musicRoots 的授权；Windows 首次启用启动时还检查各逻辑磁盘根目录下的固定下载目录，将存在且可读的目录加入默认允许范围，结果持久化后不重复探测。发现目录只授予访问权限，不自动选择音乐目录或扫描入库。显式 YAML `permissions.readDirectories` 完整覆盖默认授权，空数组表示禁止访问。

「设置 → 插件管理」中的本地音乐摘要显示“n 个允许访问的目录”，统计授权根目录，不统计子目录或已添加的音乐目录；即使尚未添加音乐目录，仍展示授权数量。「设置 → 音乐源」在「本地音乐」标题右侧提供「添加本地目录」，下方只列出已添加的目录，每行右侧提供减号删除和编辑。添加弹窗以允许访问的目录为树根，只能选择这些根或子目录，不能在添加流程取消已有目录。编辑提供目录名称和该目录的查找设置，不改变其他目录的配置；删除只移除音乐源目录配置，保留授权范围、磁盘文件与已有曲库记录。

逐目录查找设置支持递归、深度限制、隐藏内容和 .nomedia 处理；递归默认深度为 0，表示查找全部子目录。默认跳过点开头及 Windows 隐藏文件、目录，并遵循 .nomedia 跳过其所在目录及子树。Server 返回每个本地目录的有效设置。新目录省略覆盖时继承实例默认值，修改已有目录时省略覆盖则保留其设置。取消不保存；Web 添加或编辑目录配置应用成功后自动扫描。管理员也可点击「音乐源 → 本地音乐」标题行的「刷新」，为全部已添加目录逐个创建元数据刷新任务，沿用各目录设置；目录行编辑右侧的「刷新」仅创建该目录任务。页面显示任务状态和已发现曲目数，Server 每校验一页扫描结果便更新现有 `progress.observed`，无需等待元数据探测或整次扫描结束；该数量不代表已入库，完整成功后刷新曲库。待配置实例仍显示插件自述的「本地音乐」名称并可添加目录。只有管理员目录浏览接口返回这些路径，普通来源与配置展示继续脱敏；Server 从授权根句柄相对打开目录，拒绝越界及链接逃逸。客户端沿用实例配置 API 和不透明修订，不直接访问插件数据库，具体路径和边界见 [Server 插件配置](../server/docs/plugins/plugin-configuration.md)。

本地目录添加与编辑提供「导入歌词」开关；Local Files 的插件默认值开启歌词和封面导入，已保存的显式关闭设置继续生效。扫描成功后由本地元数据插件读取内嵌歌词及同目录同名的 LRC、TXT，只补缺失且未锁定的内容。已有目录可开启歌词导入后保存并扫描，也可使用目录「刷新」重新读取歌词和封面；人工选定的内容保留。

本地音乐页面会自动查询当前账号、当前来源的扫描状态，优先显示运行或等待中的任务，否则显示最近一次结果；打开、刷新、切回页面和其他窗口发起扫描时均无需再点击刷新按钮。状态查询只读，不创建扫描任务。各已添加目录右侧显示曲库中可用音乐文件的数量和总大小，不合并重复录音、不计歌词和封面附件；扫描中保留已发布统计，完整成功后自动刷新。尚未读到统计时显示加载状态，不把未知数据当作零。

Web 和桌面 Client 都提供全局任务队列，默认展示当前用户的任务，管理员可切换查看全部用户。曲目列表可将专辑批量自动刮削和全部曲目的一键合并加入队列。专辑任务按当前来源及搜索条件处理所有未刮削专辑，合并任务使用用户确认的规则与修订。两者均可在等待时取消，关闭页面后由 Server 继续执行。目录刷新任务覆盖扫描与后续元数据处理，每个目录可独立排队、取消或中断。全部刷新使用每目录独立请求和幂等键，部分提交失败只重试未确认目录。队列角标和列表通过同一 WebSocket 订阅更新，模型与权限见 [Server 任务队列](../server/docs/library/tasks.md)。

Server 在自身 `docs/contracts` 维护 OpenAPI、事件 Schema 和带版本的协议 SDK。桌面应用使用 Rust 编写，egui 绘制界面，eframe 管理系统窗口。独立的 Rust 模块负责 Server 会话和原生播放。桌面与 Web 沿用同一交互设计和服务协议，分别实现窗口、控件与音频输出。Windows、macOS 和 Linux 的构建、设备与安装验证分别记录。[Client 实现方案](../client/docs/implementation.md)与[桌面验证记录](../client/docs/validation/desktop.md)。

Android 工程由 [MusicFS-android](https://github.com/fnMrRice/MusicFS-android) 维护，检出到 `android/`，`client/` 仅维护跨平台桌面客户端。手机与平板共用自适应界面，Android TV 使用遥控器专用入口。三者由一个应用交付，共用协议适配、曲库与播放逻辑。每台设备持有本机队列和会话，通过第 7 节的 remote 模式连接 Server。

内部文档使用相对链接。跨仓库相对链接以递归检出 `android/`、`client/`、`server/`、`web/` 的工作区为基准。主仓库记录四个子模块的提交版本。

Server 使用结构化日志，默认等级为 `info`，支持 `trace/debug/info/warn/error` 与按插件覆盖。宿主和各插件分别保存日志文件，同插件多实例通过实例标识区分；旧日志按天或大小轮转，同一 UTC 日期的宿主与插件历史切片合并压缩为一个归档包，保留 30 天。管理员可通过新增日志等级接口临时调整当前进程的等级，重启后恢复部署配置；该接口不改变既有客户端协议，也不代表 Web 已提供日志设置界面。具体目录、运行时修改及敏感字段限制见 [Server 日志](../server/docs/operations/logging.md)。

当前 Server / 插件 / 最小 Web 的交付顺序与联合验收见[分阶段实施总览](implementation.md)。本文保持长期契约，具体模块和实现步骤由对应仓库维护。

Server 的 Go 插件协议与公共模型为独立 SDK 模块，仍由 Server 仓库维护；在线平台实现保留独立 Go 模块，并编入 Server 的官方内置装配。音乐源、数据库、解码、刮削、DSP 和媒体算法插件都在 Server 主进程运行，各实例保持独立配置、账号状态、上下文和通信边界。默认运行不需要插件可执行文件；`musicfs-plugins`、单平台和单用途入口只用于显式选择 `execution: process` 的外部进程兼容模式，不自动为内置插件派生进程。FFmpeg、ffprobe、fpcalc 等受控工具仍可按任务启动外部程序。模块、发布兼容与旧配置迁移见 [Server SDK](../server/docs/plugins/plugin-sdk.md)，依赖关系见 [模块图](diagrams/server-plugin-sdk.puml)。默认装配、显式禁用和待配置状态见 [Server 配置](../server/docs/operations/configuration.md)，界面不得将 `pending_configuration` 显示为已就绪。

Server 部署配置不指定实例 `role`；角色来自插件握手的 `Manifest.roles`，宿主校验后使用。名称与译名同样由插件声明，实例配置的可选 `name` 只表示管理员别名，示例与自动发现不预填名称。管理 API 的角色字段保持兼容。

Server 的业务适配按可信注册能力与公共接口执行：插件提供目录配置、登录方式、资源校验规则及音频、刮削、分析、标签处理实现，宿主保留权限、调度和发布责任。新增受信任实现可以注册替换，无需在业务流程增加官方插件 ID 分支；这不包含第三方动态安装。指纹契约使用通用分析器身份，旧证据由数据库迁移归档，需显式重算，不与新身份混用；客户端与 Server 的精确变更见 [Server 插件架构](../server/docs/plugins/plugin-architecture.md)及对应协议。

来源插件通过 `sourceType` 声明本地或网络播放路径。网络来源在创建播放会话时查询当前账号可用的音频格式，客户端请求音频时才开始读取。支持播放的在线插件共用服务端下载缓存，可按用户和插件设置容量，默认边下边播。一个来源可以保留多个音质或内容版本。用户可在曲目列表查看每个下载版本的实际音质，按需删除其中一个。缓存读取沿用账号和曲目播放授权。

下载完成后，服务端从本地音频文件读取编码、容器、采样率、声道和码率，并在文件提供有效位深时保存位深。每个下载版本单独记录测量结果。在线曲目页按当前用户和来源实例批量读取已下载版本，播放器使用本次实际命中的文件信息。

管理员可在 Web 播放设置中更改服务器保存在线音频的目录。各在线来源的手动下载和播放缓存共用此设置。每份已完成的下载记录其保存位置，后续切换目录仍可读取和管理旧版本。

在线音频具备可靠的字节长度和时长时，同一播放会话复用已下载的文件或正在写入的文件，支持拖动进度条。跳到尚未下载的位置会等待对应数据到达。Web 播放栏显示本次播放的实际声道数，可从插件提供的资料或正在播放的音频中取得。见[来源播放流程](diagrams/source-playback.puml)和 [Server 网络来源播放](../server/docs/playback/network-sources.md)。

在线歌单支持单曲、多选和整单下载。Web 在提交时展示来源插件声明的音质，Server 将所选音质和当前账号绑定到后台任务，逐首下载到同一缓存，并记录每首实际保存的版本或失败原因。中断的任务可在服务端重启后继续。

Server 来源插件 ID 统一为 `musicfs.plugin.source.xxx`，解码与音频处理插件统一为 `musicfs.plugin.decoder.xxx`；本地歌词/封面插件保留 `musicfs.scraper.local`。每个插件必须在握手中提供显示别名 `plugin.name`、译名和 `supportsMultipleInstances` 声明，管理接口返回这些信息；本地音乐、FFmpeg 和 NCM 只允许一个配置实例，四个在线平台及本地歌词/封面插件支持多实例。插件实例使用稳定 UUID，与插件 ID 和显示别名分离；在线实例名称取当前已校验账号的用户名，未登录时回退插件别名。客户端按声明展示插件与账号，不以 UUID 作为标题。旧命名、UUID 迁移及配套升级要求见 [Server 插件身份与名称](../server/docs/plugins/plugin-identity.md)。

Server 插件和实例停用只保存配置，重启 Server 后生效；当前 Worker、任务、播放及新工作准入保持。启用和实例设置仍可动态应用。管理快照及操作的 `restartRequired` 与实例 `RESTART_REQUIRED` 原因区分保存意图和运行状态；待重启时 `effectiveEnabled` 按当前运行开关计算，`appliedRevision` 不推进至新修订。旧 `mode=drain/force` 仅兼容接受，不再排空或取消。客户端不得凭保存开关或操作 succeeded 宣称已经停用，见[Server 插件管理](../server/docs/plugins/plugin-management.md)。

Web 插件管理以可展开的列表展示，每行左侧显示插件名称，版本号在列表中右对齐。若插件提供数量说明，说明紧邻名称。支持配置的插件在行末显示「配置」按钮。展开后可查看用途、插件 ID 及对应的实例或基础设施状态。刷新按钮位于搜索框右侧。用途来自插件的 `features` 声明，例如音乐源、音频编解码、DSP、元数据。NCM 与 FFmpeg 声明 `audio-codec`，声道转换声明 `audio-dsp`；`transform/thumbnail`、`tags/*`、`scraper/*` 插件统一声明 `metadata`，在列表与类型筛选中归为“元数据”。分类不改变已有插件 ID、源码路径、协议角色或业务能力。类型筛选支持多选，默认空选显示全部，清空选择也显示全部；多个类型匹配任一项即可。ID／名称搜索不区分大小写，与类型筛选组合生效，刷新保留当前筛选。所有插件必须声明有效发行版本；随包插件尚未启动时采用与 Worker 同源的版本声明，成功握手后使用实际版本；具体版本校验及协议兼容由 Server 维护。

摘要不展示实例数量，可选数量及单位通过 `displayCount` 提供：本地音乐的授权目录数量由掌握权限配置的 Server 统计，Worker 不接收未添加目录的授权路径；需要登录的在线插件报告已登录平台用户数量。Server 只按当前可见范围汇总同单位统计，Web 仅选择响应提供的单位译文，缺失时隐藏，不自行推算。登录插件的每个实例属于一个 MusicFS 用户，并独立承载一个平台账号；同一用户的不同平台账号也使用不同 UUID 实例。管理员默认查看自己的在线实例与共享实例，可勾选“显示所有用户实例”查看全部归属；此项只扩大管理员管理视图，不扩大平台账号的业务访问权限。具体管理字段、部署归属配置及兼容范围由 [Server 插件管理](../server/docs/plugins/plugin-management.md)维护。现有 MusicFS 登录入口仍仅创建管理员会话，实例归属能力不代表已交付一般用户注册与账号管理。

### 1.1 插件化决策与执行边界

2026-10-21 服务端增量：官方内置 DSP 和 SQLite 与其他内置插件一起在 Server 主进程运行，显式外部模式保留专用协议。内置 DSP 提供增益、参数均衡器、压缩器、混响，保持协商后的 PCM 格式、帧数与零算法延迟，不追加曲尾；有状态定位从曲首重建后按帧裁切。独立声道转换插件属于 DSP，位于效果链前，支持立体声、5.1、7.1 输出，分别使用 MP3 或 Opus/WebM；外部 MFD1 v1 仍只接受无状态双声道节点。存储是必需组件。部署默认使用 SQLite，也可在 YAML 中选择 PostgreSQL，主库和插件实例私有状态使用同一后端。数据库、声道转换与 DSP 纳入统一插件列表，只读展示配置与能力，不把配置状态表述为正在处理音频；部署配置修改后重启生效。数据库插件维护主库与实例库的 Schema 和迁移，在返回后端前完成初始化；宿主保留业务数据与事务契约、数据锁、生命周期与文件发布协调。公共播放描述报告实际声道布局、编码和处理顺序，按包含转换版本、布局和效果参数的身份隔离缓存与恢复；客户端必须协商对应 MIME，格式支持不等于音响设备已经输出物理环绕声。具体范围见 [DSP 与声道转换](../server/docs/plugins/dsp-effects.md)及[存储插件](../server/docs/plugins/storage-plugins.md)。

2026-10-22 Web 本地 DSP：Web「设置 → DSP 配置」以默认收起的紧凑列表编辑本地增益、十段均衡器、参数均衡器、动态压缩和混响，可增删、拖动排序、旁路效果及实时调整参数。十段均衡器提供竖向频段滑杆、预设和低音／高音增强。调整立即用于试听，点击保存才写入当前浏览器；可撤销到上次保存配置，按 Server 实例和账号隔离，不自动导入原服务端效果链。浏览器解码后的音频依次经过 Web Audio 效果链、本地输出布局、可选自动音量平衡、可选的淡出淡入及末端音量节点，调参不重新请求播放会话或重启音频流。自动音量平衡默认关闭，开启时逐声道估计 RMS 和峰值，统一调整增益。淡出淡入总开关默认开启，切歌、暂停和跳转的时长可分别设置。「输出设置」提供跟随音源、单声道、立体声、5.1 与 7.1，以及默认关闭的立体声环绕扩展，独立于音效总开关并单独保存。默认跟随音源，受浏览器报告的设备声道上限约束，无法使用保存的布局时降级输出但保留偏好；模拟环绕不等同于原生多声道，实际扬声器输出依赖系统和设备配置。本地处理不受服务端 DSP 缓冲区设置控制。实现边界及验证见 [Web 本地 DSP](../web/docs/dsp-settings.md)。

Server 保留原 DSP 与声道转换实现，`audioDSP.enabled` 和 `audioChannels.enabled` 默认关闭，停止装配音效与声道扩展插件；解密、解码、格式转换和转码继续可用。Web 创建播放会话始终声明 `preferences.dspExecution=client`，Server 在会话内固定无音效、无声道扩展的处理视图，定位与恢复也不重新应用个人、全局或部署音效链和目标布局。可播放音源保留原声道，仅在编码格式不支持时进行必要兼容适配，不调用声道扩展插件。响应 `dspExecution` 确认归属，`effectiveProcessing` 仅描述实际服务端处理；Web 拒绝未确认本地执行或仍包含服务端音效的描述，防止重复处理。本地参数和输出布局变化不改变服务端表示、缓存及时间轴身份。原服务端 DSP 的插件格式验证、64–16384 帧缓冲区和不可变快照逻辑保留，显式启用后供服务端执行模式使用，详见 [Server DSP 配置](../server/docs/plugins/dsp-settings.md)及[本地音效链路](diagrams/web-local-dsp.puml)。

四类新增内置算法通过 Go 接口注入：音频分析为 `plugins/analysis/chromaprint`，接入 `fingerprintworker.Extractor`；标签格式为 `plugins/tags/flac`，接入 `sdk/tagformat.Format`；匹配评分为 `plugins/matching/standard`，接入 `candidates.Scorer`；内容变换为 `plugins/transform/thumbnail`，接入 `sdk/contenttransform.Thumbnailer`。当前分别实现已有 Chromaprint 指纹、FLAC 标签重写、标准候选评分、PNG/JPEG 缩略图，不代表 BPM/调性、ID3/MP4、任意评分模型或歌词对齐已经实现。插件发行版本独立声明，但内置版本随 Server 重新构建和交付；不提供任意第三方代码加载。授权、任务、资产版本、人工确认、原件替换和结果发布仍由宿主负责。

插件管理的功能分类与上述接口分工分别声明：Chromaprint 指纹提取和标准录音匹配归入“音频分析”（`audio-analysis`）；本地元数据提取、标签格式和封面缩略图归入“元数据”（`metadata`）。分类由 Server 的插件身份声明提供，Web 按声明展示与筛选；标准录音匹配仍保留原名称、候选评分及设置能力。

可替换的来源适配、媒体算法、格式处理、外观与控制接入优先使用有版本的插件接口；身份、授权、状态所有权、事务发布和生命周期协调留在宿主。现有 C/S 架构支持这个方向，但“允许扩展”不代表“当前 SDK 已接受所有插件类型”：新增角色和扩展 NAS/在线音频资源通道须先补对应宿主契约，具体缺口见[跨端插件边界](plugin-boundaries.md)。

Client 原生插件统一在 Rust 原生宿主的同一进程内加载，Windows 为 DLL、macOS 为 dylib、Linux 为 so，不设置 PluginWorker、插件子进程或独立音频引擎进程。主题仍为声明式资源包。Client 不提供插件卸载，已加载库保留到进程退出；插件启用、停用、更新和回滚保存为期望设置，统一重启后生效，界面区分当前状态与下次启动状态。插件宿主仍属后续实施阶段。插件故障可能终止整个 Client，清单权限不是原生代码沙箱。

Server 内置插件与宿主共享进程，取消和退出依靠协作，不具备插件崩溃、内存破坏或卡死隔离；不能通过强杀插件线程保证服务继续运行。只有显式配置的外部进程插件使用独立进程与回收机制，进程隔离仍不等于操作系统权限沙箱。需要 C++ 的插件与自有适配层统一用 CMake/C++23 开发；Client 通过版本化 C ABI 加载，未来 Server 内置 C++ 适配也必须留在主进程，具体桥接尚待实现与验证。外部 C++ 可执行插件可按显式进程模式适配已有 IPC。两端可复用算法源码，但独立构建、适配、发布和验收；不承诺共用 DLL，也不将现有 Go/Rust/TypeScript 实现统一改写为 C++。

## 2. 跨端职责与可见能力

作品库依次提供曲目列表、CD专辑、ASMR、电台。后面三项由独立内容插件声明。ASMR 与电台各自浏览，CD 专辑可按作品选择将已导入的音轨同时显示在普通曲目列表，默认关闭。各库共享来源身份、文件授权和播放链。当前支持本地文件、作品包目录及附件，自动包同步和 CUE 分段播放属于后续阶段。[本地音频作品库与内容插件扩展](content-library.md)

Server 汇集本地音乐文件、已挂载 NAS 与在线平台来源，提供统一音乐库、歌单、来源选择和音频交付；桌面、Web 与 Android 客户端负责展示、用户操作和播放。Local Files Provider 属于首版范围：这里的“本地”指 Server 可访问的文件系统，远程 Client 的本机路径不能直接交给远程 Server 读取。客户端上传或共享整首音频若需要，另行设计。

界面根据 Server 返回的实例与能力展示操作，不预设每个 Provider 都能搜索、扫描、登录、读取歌单或推荐歌单。网易云、QQ 音乐、Apple Music 是目标来源，这三个 Music Provider 插件必须提供对应平台的用户登录/授权能力；具体登录方式与推荐、播放、付费内容能力须逐平台验证。此项是交付要求，不代表已实现。推荐结果保留平台排序、来源、账号/匿名范围、有效期与分页状态；允许按来源分栏及部分失败。打开推荐项不自动加入用户歌单，用户选择导入或绑定后才进入歌单库；推荐列表变化不删除已导入歌单，也不触发远程写回。推荐可见不代表歌曲一定可播放。

音乐来源的插件身份、默认显示名、各语言译名和 `music-source` 功能由插件声明，Server 校验后传给客户端；Client / Web 不维护平台 ID 到名称或译名的固定映射。界面按当前语言选择插件译名，缺少匹配时使用插件默认名；插件 ID、实例 ID、管理员设置的实例别名和平台账号昵称保持独立语义，设置页的平台标题不拼接实例别名。本地来源与在线来源统一放在“音乐来源”区域，需要登录的插件在对应来源中提供账号操作。尚未取得有效声明时显示通用未知来源提示，不从实例编号推断平台名。当前协议字段及升级要求见 [Server 插件身份与名称](../server/docs/plugins/plugin-identity.md)；桌面推荐页根据 Server 的来源信息展示名称，完整的来源账号管理按此契约扩展。

歌单管理页和左侧歌单列表通过来源的 `playlist.list` 能力读取已登录账号的歌单。网易云账号歌单目录和每张歌单详情在服务器本地日期的首次打开时更新，当日再次打开复用最新结果。用户可手动刷新目录或当前歌单。退出平台或切换账号时清理旧列表和未完成的读取请求。

推荐页在支持 `recommendations.tracks` 的账号推荐歌单中展示「每日推荐歌曲」卡片。打开卡片后才读取当前账号的曲目，按平台顺序展示。Web 推荐页的各来源分组默认展开，可分别收起。用户可在外观设置中调整来源的显示顺序，组内卡片沿用原序。歌单推荐按来源保存快照，用户可在「时光机」浮层中选择要查看的轮次。

用户可将本人可写的网易云歌单关联到本地歌单或「我的收藏」。关联和导入都会在后台读取远程曲目，按来源实例及平台曲目编号建立曲库记录。关联还把这些曲目加入所选目标。之后向目标添加同平台曲目时，Server 安排向远程追加。同一远程歌单只关联一个本地目标。排序、隐藏及删除保留在本地。详见[来源歌单](../server/docs/library/source-playlists.md)。

关联后可以点击「立即同步」，从平台重新读取完整歌单，并把新增曲目及其来源补入目标歌单。多个并发请求共用同一项进行中的同步任务。任务成功后 Web 更新曲目列表，读取失败时保留上次成功的内容。

网易云曲目作为新来源首次入库时，若能唯一匹配到用户已有的本地录音，就加入该录音的来源列表，歌单和收藏使用同一首曲目。重新同步已入库的来源会保留原有分组。详见[重复识别](../server/docs/library/duplicate-detection.md)。

曲库与播放队列优先使用已选录音封面。缺图时，Server 按需从网易云补取并校验图片，再将其绑定到曲目。后续从本地媒体库读取。在线插件为账号状态查询单独分配并发名额，曲库根据插件运行状态和账号状态展示可用性。显示在线歌曲的播放格式时，播放器使用本次会话实际交付的编码、码率与可用的采样率。

歌词、封面等内容由独立 Scraper 插件提供，自动与手动刮削共用候选/选用流程，不要求先启用在线 Music Provider。界面支持选择目标、插件和字段，调整查询、预览候选、逐字段选用、上传或编辑。预览不覆盖已发布内容，手动选用受修订检查并记录人工锁定；自动刷新不覆盖人工结果。取消或失败保留已发布内容，批量任务逐项显示结果。

在线资料来源声明 `type=scraper` 和各自支持的内容，如专辑详情、按碟排列的曲目、歌手图像、歌词或录音识别。Web 从服务端读取声明并按字段筛选来源；作品选用结果带来源编号和链接，曲目选用歌词或封面后可经媒体库读取。「曲目列表 → 专辑」的卡片与标题展示专辑封面，优先采用已选平台封面，再回退专辑及可见曲目封面。专辑名右侧的「详情」默认收起，展开后以标签展示原名、显示名、艺人、发行日期、发行商、音乐风格、曲目表等资料，并提供平台页面链接。详情中的「搜索」位于「刷新资料」左侧，可按名称或支持的平台专辑页查询，取得同一发行版的详情和完整曲目表后预览并一次选用。选用按用户、专辑修订和幂等键原子保存，并补齐实际专辑曲目资料；缺少音源的曲目在专辑和歌手内灰显，已有音源和手工资料保留，重刮同一发行版不重复创建条目。专辑原名在首次导入时保留，显示名、发行商和发行日期可独立编辑。来源筛选不改变保存目标；未知专辑不提供共同刮削目标，不写原始音频文件。已接入来源及字段见 [Server 在线资料刮削插件](../server/docs/metadata/online-scrapers.md)。

在专辑详情中点击「搜索」可同时查询多个平台，并分别保存各平台的专辑页面。再次预览同一发行版时可以复用已有的详情和曲目表。用户可在预览中手动刷新，也可在已关联专辑的「刷新资料」中选定平台，重新读取后逐项对比显示名、艺人、日期、发行商、风格、补充信息、封面和曲目表。只有勾选的字段会写入曲库。单独编辑链接只更新关联。

Web 的「曲目列表 → 专辑」支持筛选未保存任何刮削字段的专辑。自动刮削按实际音源搜索，网易云音乐和 QQ 音乐使用对应平台，本地音源按账号配置的优先级查找，默认顺序为 MusicBrainz、Apple Music（iTunes）、网易云音乐。单张与批量自动刮削都用专辑名及原始音源的艺人署名查找发行版，也会只用专辑名检索合辑。至少一首候选曲目的曲名与本专辑的一首真实音源曲目相符，且该曲目的署名与音源至少有一位艺人相同，才会按原修订保存。上次刮削生成的无音源条目不参与核对。更新已有刮削资料前会请用户确认发行版。

曲目和歌手都能保存及搜索多语言别名。Apple Music 的曲目按专辑编号和歌曲编号关联不同商店的名称。专辑刮削结合已保存的平台身份、曲名别名、歌手署名和时长来匹配已有曲目。曲目主行的更多菜单提供「编辑曲目元数据」和「搜索在线资料」。在同一专辑勾选多首曲目后可手动「合并歌曲」，选定保留的曲目，逐字段选择或编辑最终资料。服务端在同一事务中保存最终资料、归并音源并转移歌单和专辑引用。

客户端按受鉴权的对象引用读取歌词、封面等内容。默认不写原始音频，允许对经过授权且支持安全写入的本地/NAS 目录启用写回。手动刮削或上传不自动开启写回；写回成功后歌曲身份和歌单关联保持，音频文件资产版本更新。独立内容文件的存储、匹配、写入和恢复机制见 Server 文档。

曲目列表已接入歌手、专辑标签、流派和文件夹分类，分类集合及成员查询由 Server 在分页前完成；文件夹只返回目录名称和不透明身份，分类数量按当前分类可见曲目统计。「全部曲目」仅展示拥有普通曲库可见来源的曲目，由 Server 在分页前过滤；来源离线或暂不可用不等同于没有来源。专辑和歌手内仍可展示没有来源的曲目资料，整行文字使用灰色，播放操作不可用，收藏及歌单操作继续可用。分类内按曲目资料展示条目，全部曲目仍可按 Recording 聚合。列表返回可空 `coverObjectId`，Web 曲目行和播放栏读取受鉴权媒体对象。Local Files 扫描默认补齐内嵌或同名旁置封面，以实际图片像素面积、短边优选高清候选，并保留人工选用；提取文件默认保存到部署指定 `dataRoot/media/objects`，显式媒体根配置仍可覆盖，不依赖源码目录。合并版本也默认采用分辨率较高的成员封面，支持独立保存人工偏好或恢复自动，来源封面及默认播放来源不随之改变。历史曲目重新扫描并等待补齐完成后刷新列表。精确查询和保存语义见 [Server 曲库查询](../server/docs/library/catalog-query.md)及[媒体补齐](../server/docs/metadata/metadata.md#导入歌词与自动补缺)。

歌手署名按半角 `/` 分隔，在曲目入库时去除各名字首尾空白、空项及精确重复项，并保留署名顺序；合唱曲目同时归入每位歌手的分类，每个分类内只计数一次。Server 通过数据库迁移更新已有曲目，接口仍返回 `artists` 数组，Web 使用 ` / ` 展示完整署名，无需重新扫描音乐文件。具体规则见 [Server 曲库查询](../server/docs/library/catalog-query.md#曲目分类浏览)。

同一曲目从多个音源取得同名专辑标签时，收藏、歌单和曲库只展示一次专辑名。已有独立刮削资料或人工维护的同名发行各自保留。曲目保存完整的专辑成员编号，按来源或专辑浏览、编辑成员时仍能定位原记录。

### 2.1 在线平台账号登录

登录与业务接口优先参考开源项目中已验证的模拟客户端方式，采用相应客户端的请求路径、参数、加密/签名、设备标识及会话机制，不以仅修改 User-Agent 代替客户端适配。按平台和接口逐项验证；客户端方式不可用时可采用已验证的 Web / 官方 SDK 方式，并记录原因、参考版本和限制。具体接入与证据见 [Server 平台账号登录](../server/docs/providers/platform-login.md)。

网易云、QQ 音乐、Apple Music 都是必须登录的在线源。除实例发现、能力说明和登录/退出控制面外，搜索、资料、推荐、歌单预览、导入、同步及播放请求都要求对应实例具有已校验的平台账号；未登录、过期或重启后尚未校验时拒绝业务访问，不回退到匿名接口或旧缓存。网易云实例恢复已保存的凭据后，Server 在首次列出来源、读取账号状态或使用该来源时自动向网易云核对账号。凭据有效即可继续使用，暂时无法连接时保留绑定供下次访问重试，授权过期后需重新扫码。请求使用本实例账号会话，缓存与分页游标绑定账号及登录代次。

平台登录是用户登录网易云、QQ 音乐或 Apple Music 自己的账号，与访问 MusicFS Server 的 `/auth/session` 是两套独立状态。登录 MusicFS 不表示已登录任何音乐平台；三个平台分别登录、重新授权和退出，互不代替。Local Files 等无需账号的 Provider 不受此要求影响。

- 插件负责适配对应平台的登录/授权流程、账号状态校验及平台允许的会话续期；Client / Web 提供交互入口，Server 管理用户与 Provider 实例的账号绑定。扫码、跳转授权或其他方式仅在对应插件和运行端验证支持后展示，不预设三个平台采用相同流程。
- 登录交互须支持发起、等待用户操作、完成、取消、超时及失败；账号状态区分未登录、已登录、已过期/需重新授权。登录挑战绑定发起用户与实例并有有效期，取消或过期后的回调不能重新绑定账号。
- 账号与私有数据按 MusicFS 用户、Provider 实例和平台账号隔离。登录后刷新可用能力与权限；登录成功不代表拥有会员、付费内容或完整音频播放权限。Apple Music 的用户授权与播放接入须分别验证，不能据登录成功推断可由 Server 获取或处理裸流。
- 网易云账号页显示平台已确认的会员身份。会员标志随账号校验更新，平台未提供可识别的标志时，客户端只显示登录状态。具体歌曲的播放和音质仍由平台逐次授权。
- 平台凭据仅交给必要的受控授权流程及对应插件使用，服务端托管凭据不回传普通界面，不写入日志、普通配置导出或 Git。账号视图可附带平台显示名与可选头像地址；缺少头像时客户端显示默认头像，旧 Web 可忽略新增可选字段。严格解码的 Server Host 与 Worker 须配套升级；头像地址的校验与图片来源限制由 Server 契约维护，不将显示名或头像当作账号身份。若平台授权必须在客户端 SDK 中完成，其令牌范围、保管和传递方式需在实现契约中单独验证，不向其他插件共享。
- “退出平台账号”解除 MusicFS 中该平台账号的授权使用并清理所托管凭据；上游撤销能力按平台实际支持报告，不宣称退出平台其他设备。阻止该账号后续请求并失效私有缓存及相关播放授权，保留已导入的歌单和音乐库记录并更新可用性。MusicFS 会话退出不等同于解除平台绑定。

登录 API、事件与插件 SDK 的精确字段由 Server 仓库维护，并同步评估 Client / Web 兼容性；本节只定义共同需求。每个平台均须有真实账号的登录、重启后状态校验、失效后重新授权、取消/超时、退出和跨用户隔离验收，匿名访问或手工预置凭据不能替代用户登录功能验收。

### 2.2 NAS 直连与 Bilibili 音频增量

新增 NFS、SMB 两个独立 NAS Music Provider 的设计，直接连接管理员授权的 NAS 共享/export；已挂载 NAS 继续由 Local Files 提供，三种方式不自动合并或迁移来源。首批只读扫描、元数据和播放，NAS 凭据与端点仅由 Server 管理；客户端只访问受鉴权的音乐库与播放地址。离线、扫描不完整或共享身份改变时保留已有曲目与歌单，不当作空库。协议版本和安全选项须分别实测，详见 [NAS Provider 设计](../server/docs/design/nas-providers.md)。

Bilibili Provider 以公开内容匿名读取/播放为基础，登录是私有或受限功能的可选授权，不是启用插件的条件；MusicFS 自身鉴权仍然必需。B 站收藏夹为主要远程歌单来源，音频区独立歌单作为补充；两类均可预览、显式导入或绑定同步，保留来源类型、顺序、权限和全部出处，不向平台自动写回。公开视频音轨按分 P 建立曲目，音频区曲目使用独立身份；收藏夹展开分 P 的策略由用户预览确认并保存在绑定修订中。

公开视频、公开收藏夹、音频区曲目/歌单及账号功能分别声明能力并验收；音频区暂不可用不影响已验证的视频/收藏夹能力。B 站不沿用第 2.1 节三个音乐平台的强制账号交付前置要求；若接入账号，仍遵循该节的用户隔离、授权失效及退出语义。账号失效、集合转私有或分页不完整不能发布空歌单覆盖旧快照。详见 [Bilibili 设计](../server/docs/design/bilibili-provider.md)。

NAS 与 B 站音频统一进入 SourceTrack/SourceAsset、播放协商与恢复流程，不向客户端泄露 NAS 路径/凭据或短期 CDN 授权头。分 P 序号、标题、元数据摘要和播放 URL 不是固定资产版本证据；无法证明固定字节表示时不能宣告稳定 Range 或拼接旧偏移。SDK、资源通道和在线资产建档仍需扩展，实施顺序见 [NAS / Bilibili 增量计划](../server/docs/design/nas-bilibili.md)。

## 3. 共同身份与版本语义

以下是 API 暴露的数据语义，不是数据库表设计。

一首曲目可以先建档，之后再关联一个或多个真实来源。曲目和来源分别记录添加时间及修改时间。歌曲资料属于曲目，插件、实例及插件内的记录 ID 用于定位来源，格式、可用性和字节版本用于选择与播放。没有来源的曲目可浏览，播放控件不可用。同一首歌曲的手动默认来源及自动排序沿用既有规则。[曲库实体关系](diagrams/music-catalog.puml) · [Server 数据模型与接口](../server/docs/library/music-catalog.md)

歌单的每个本地条目保存曲目及可选的强制来源。留空时使用播放时的默认版本，指定后只用该来源。收藏、音乐最近播放使用特殊歌单。各作品插件通过 `library.separateHistory` 声明独立历史，由插件保存、排序及读取本账号的记录；历史页据此在音乐旁显示 CD 专辑、ASMR、电台标签。

| 标识 / 对象 | 跨端约定 |
| --- | --- |
| 曲目 | 由稳定内部 ID 标识，必填曲名，歌手、所属专辑、封面、流派、年份和个人星级可空 |
| 歌手 / 专辑 | 歌手名与专辑名必填，可分别关联多首曲目。专辑可保存外部编号、外部专辑标记、封面地址、发行商与发行日期 |
| Recording | 某个录音版本的内部标识；Live、Remix、翻唱分别处理，不以歌名 + 歌手作唯一键 |
| SourceTrack | 某 Provider 实例下的来源曲目，保留出处与可用性；未匹配到 Recording 也可播放 |
| SourceAsset | 来源曲目某个音质的具体字节版本；内容改变产生新版本，不能静默替换活动播放资源 |
| 匹配证据 | 码率属于具体资产；SHA-512 表示完整文件字节摘要；音频指纹辅助发现相似音频候选；三者均不能单独证明跨源时间轴兼容 |
| PlaylistEntry / provenance | 稳定条目标识及全部来源出处；聚合展示行不作为持久身份 |
| revision | 歌单、选择或规则的修订；分页固定同一修订，编辑携带预期修订 |
| MediaObject / selection | 歌词、封面等不可变内容对象与当前选择；返回受鉴权引用、版本、来源和适用范围，不返回 Server 磁盘路径 |
| PlaybackSession | 用户、设备与播放目标上下文；会话不能代替具体资源版本 |
| attemptId / representationId | 一次播放尝试及其固定输出表示；源资产、处理配置、输出格式或生成起点改变时返回新标识和新地址 |

Server 返回的资产信息可包含 codec、container、durationMs、bitrateBps、bitrateMode、fileSizeBytes、fileSha512 及探测状态。未知值为 null；码率单位 bit/s；已校验的完整文件 SHA-512 在协议中表示为 128 个小写十六进制字符。Provider 申报值与 Server 计算值区分展示，未知摘要不阻止播放。文件不同、码率不同或摘要不同不直接等同于不同 Recording；人工关联与禁止关联优先于自动建议。具体探测、摘要、指纹提取及证据管理见 [Server 内部架构](../server/docs/architecture.md)。

重复识别与人工关联分开：识别规则、评分和对应设置声明由匹配插件提供；后台执行、权限检查、候选发布和持久化由 Server 管理。插件仅提出待确认候选，不能自行合并 Recording。人工关联、解除和排除属于 Server 自身能力，即使自动识别关闭，用户仍可在曲目列表勾选歌曲并点击「合并歌曲」。关联只改变 MusicFS 中的逻辑关系，保留每个来源与原文件。

Web 的「一键合并重复音乐」由用户显式执行，可选择按候选分数阈值或按重名重作者合并。Server 在一次事务中处理全部来源中当前用户可见且可用的曲目，不受页面分页或来源筛选限制；分数模式只使用当前有效候选，重名重作者模式比较非空完整曲名和作者集合，不依赖识别插件。合并保留已有录音组的完整成员（含组内暂不可用来源），尊重人工排除及解除关联，跳过冲突或超过单组上限的组合，并返回实际合并及跳过数量。该操作不删除来源或文件，不产生跨来源时间轴证据；同一操作键重试返回原结果，关联修订冲突要求重新选择。打开合并弹窗时读取关联修订，提交时由 Server 检查修订。详见 [Server 重复识别与批量合并](../server/docs/library/duplicate-detection.md)。

Web 曲目列表从 Server 分页读取曲目资料，已确认的录音关联决定哪些来源属于同一曲目。多版本歌曲可展开查看各来源、格式、码率、文件大小和时长，并分别播放或解除关联。自动默认优先选择可用来源，再按音频码率、原文件大小降序选择，未知值排在已知值之后，仍相同时使用稳定的名称和来源身份顺序。用户可手动指定同组默认来源，也可取消指定恢复自动选择；偏好按用户和 Recording 持久保存，手动来源暂时不可用时保留指定并显示不可用，解除关联或移出分组后不再作为该组默认。用户未执行合并时，同名、相似时长或候选评分不会直接改变分组。分页同时绑定曲库与人工关联修订，避免跨页遗漏来源或拼接变更前后的分组。主行播放使用当前默认来源。点选某个版本或给歌单条目设置强制来源时，播放器使用指定的 SourceTrack。

Web 曲目列表表头全选保存当前查询的全选状态及单项排除，包含尚未加载的曲目。曲目主库按 `trackId` 选择，执行批量操作前按同一查询分页解析所选曲目；播放与人工合并再展开具体来源，不混用曲目身份与来源身份。来源曲目列表的批量请求携带 `batch/exclude`、来源过滤、录音分组和曲库／关联修订，Server 在事务内按同一可见范围解析并处理收藏、歌单追加及人工合并。排除代表曲目会排除整行，合并展开其全部版本并继续遵守单组上限。浏览器队列数量随所选曲目增长。精确字段、限额与修订冲突见 Server 契约；这不代表桌面 Client 已接入。

展开后的每个来源版本提供“详情”入口，按该 SourceTrack 路由到所属来源插件，由插件返回标题、分组与只读文本字段；Server 校验访问权限、来源身份、当前版本及响应结构，Web 通用展示，不维护平台字段映射，也不使用列表摘要冒充插件详情。本地插件展示来源内路径、大小和文件版本等实际可验证的信息，不暴露服务器绝对路径；在线插件按真实能力提供平台元信息。详情加载失败可重试，关闭弹窗后丢弃未完成请求的结果，不改变歌曲关联或播放状态。契约见 [来源曲目详情](../server/docs/library/source-track-details.md)。

插件可提供声明式设置页面：包括文字输入、数值输入、开关、下拉选择和操作按钮，由 Server 校验声明与参数，Web 统一渲染。设置和动作按插件声明分派，插件页面不承担人工关联业务，也不直接执行任意网页脚本或请求地址。具体字段、兼容规则与支持插件以 Server 的 SDK 和 OpenAPI 为准，见[插件设置](../server/docs/plugins/settings.md)、[重复识别](../server/docs/library/duplicate-detection.md)及[录音聚合曲库](../server/docs/library/recording-groups.md)。

Web 插件列表为声明设置能力的插件提供独立「配置」按钮，折叠时也能打开设置弹窗。在线刮削插件自行声明网络设置，按当前用户和插件分别保存，可选择跟随服务端环境、直连或自定义 HTTP／HTTPS／SOCKS5 代理。保存后，新查询及服务端封面下载使用对应设置；请求派生独立客户端，不改变其他插件的连接方式。跟随环境读取服务端的 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`，具体地址限制见 [Server 在线资料刮削插件](../server/docs/metadata/online-scrapers.md)。

NCM 的 SourceAsset 仍标识原始加密容器，文件大小、摘要与版本属于原文件；解密出的 MP3/FLAC 是独立播放表示，不覆盖源资产。解密表示使用自己的长度、验证器与 representationId；客户端的 Range 面向该表示，不能沿用加密文件的字节偏移。

## 4. API 与事件草案

业务路由前缀 `/api/v1`。错误包含 `code/message/requestId/retryAfter`，绝对时间采用 UTC ISO 8601，曲目位置和持续时间使用毫秒，列表使用游标。下面保留共同目标中的 API 族；已经交付的精确路径、字段、能力与错误码以 [Server OpenAPI](../server/docs/contracts/openapi.yaml) 为准，不能由草案路由推断接口存在。连接保活、播放控制、生命周期租约与状态通知统一通过 [WebSocket 控制通道](../server/docs/contracts/control-channel.md)，音频与普通数据查询继续使用 HTTP。

| 路由 | 共同语义 |
| --- | --- |
| GET /health/live、/health/ready | 返回存活或就绪状态、MusicFS 身份、实例 ID、服务端发行版本和协议版本。授权另经会话握手。Web「设置 → 关于」展示连接的服务端版本与当前 Web 构建版本。 |
| POST /auth/session、GET /auth/session、DELETE /auth/session | 最小 Web 的凭据交换、会话恢复与退出；流使用同源会话授权 |
| GET /providers、/provider-instances | 用户可访问的 Music Provider 实例、能力及账号状态 |
| GET /scrapers、/scraper-instances | 独立刮削插件、实例、能力及状态 |
| POST /provider-instances/{id}/scan-jobs | 触发授权本地/NAS 来源的扫描，返回 jobId |
| GET /scan-jobs/{id} | 扫描状态、进度、完整性、错误、执行次数、下次重试时间与上次成功时间；retry_wait等待服务端调度，paused需要处理原因后显式重提 |
| GET /source-tracks | 用户可见来源曲目，按实例过滤与固定 libraryRevision 游标分页 |
| GET /library/categories、GET /library/search | 歌手、专辑标签、流派、文件夹分类及曲目成员的固定快照查询 |
| GET /search?q=...&cursor=... | 按来源部分成功，候选关联不强制折叠 |
| GET /recordings/{id}/sources | 可选来源、音质信息与当前用户可用性 |
| GET/PUT /recordings/{id}/cover | 读取有效成员封面，人工选用或恢复最高分辨率自动选择 |
| GET /recommendations | 按可访问来源聚合。按服务器本地日期每日首次打开更新，其后读取当日结果。支持手动刷新，时光机可回看最近五次历史推荐。各来源保留账号范围、原有顺序和失败状态 |
| POST/GET /playlists、GET/PUT /playlists/{id} | 本人歌单及有序聚合规则，整体编辑携带预期规则修订 |
| POST /playlists/{id}/rebuild、GET /playlists/{id}/snapshots/{revision} | 生成聚合快照并按固定修订分页，保留所有出处 |
| GET/POST /playlists/{id}/hidden-rules、PUT /playlists/{id}/hidden-rules/{ruleId} | 持久隐藏意图、修订更新与扩大目标时的显式确认 |
| POST/GET /remote-playlists、POST /remote-playlists/{id}/sync-jobs | 导入远程绑定、显式创建同步任务；请求成功不等于快照已发布 |
| GET /playlist-links、PUT/DELETE /online-instances/{id}/playlists/{externalId}/link | 查看、建立或解除账号远程歌单与本地歌单的追加关联 |
| GET /remote-playlist-sync-jobs/{id}、GET /remote-playlists/{id}/snapshots/{revision} | 同步状态、保守移除及固定历史快照 |
| GET /source-tracks/{id}/media | 歌词/封面版本、来源、语言、时序适用范围与当前选择 |
| GET /media/{objectId} | 鉴权后读取文件内容 |
| POST /metadata-jobs、GET /metadata-jobs/{id} | 创建刮削/预览任务；读取进度、逐目标状态、候选及预览引用 |
| POST /metadata-candidates/{id}/apply、/metadata-jobs/{id}/cancel | 按目标修订应用选用结果，或取消未完成工作 |
| POST /media | 上传/编辑生成新的内容对象，不直接替换当前选择 |
| PUT /source-tracks/{id}/media-selection | 按预期修订选择内容并记录人工锁定 |
| POST /metadata-write-jobs | 按既有授权配置、预期资产版本申请写入原文件，返回任务状态 |
| POST /playback/sessions | 提交 recordingId/sourceTrackId、偏好和客户端能力，返回播放描述 |
| DELETE /playback/sessions/{id} | 幂等停止本人会话并释放资源 |
| POST /playback/sessions/{id}/recover | 提交 attemptId、可观察故障和 positionMs 曲目时间，取得恢复描述或明确的用户操作要求 |
| GET /playback/recovery-profile、POST /timeline-evidence、GET /timeline-evidence/{id} | 获取处理配置及创建/读取人工时间对齐证据；撤销使用POST /timeline-evidence/{id}/revoke |
| POST /playback/sessions/{id}/recover-source | 对当前attempt申请指定目标来源，证据适用时continue，否则promptRestart；不按指纹相似度自动推导偏移 |
| POST /playback/sessions/{id}/seek | 对 timeRestart 输出提交 attemptId、positionMs，返回新尝试和新输出地址 |
| GET /playback/sessions/{id}/attempts/{attemptId}/stream | 鉴权交付该次尝试的固定表示；客户端使用返回的 streamUrl，不自行拼接 |
| GET /control | `musicfs.control.v1` WebSocket，承载播放控制、显式租约续期、心跳，以及能力、后台任务与本机生命周期通知 |
| GET /lifecycle、POST /lifecycle/leases及续租/释放子路径 | 本地鉴权的启动归属与多客户端租约；仅client-managed模式自动收尾，不代表桌面启动器已经实现 |

客户端把表中的播放创建、停止、seek、recover、recover-source 及生命周期 method/path 放入 WS `request` 消息，path 不带 `/api/v1` 前缀；响应复用 HTTP 状态和 JSON 正文。对应 HTTP 控制路由保留为管理入口，不作为断线兼容层。升级检查登录 Cookie、允许的 Origin 及子协议，5 秒内首帧 `{type:"auth",csrfToken}` 通过后才能控制；ready 返回实例身份、10 秒心跳间隔和 30 秒消息超时，每次心跳及命令重新核验登录。

创建任务、会话及可能重试的播放控制请求支持幂等键，HTTP 使用 `Idempotency-Key`，WS 使用 `idempotencyKey`。seek/recover 必须校验请求所属尝试，过期请求不能覆盖较新的播放状态。采用 `If-Match` 的修订检查失败返回 412，其他业务状态冲突使用明确的 409 错误。WS `capabilities.changed` 数据含 `revision/sequence`，用于刷新授权来源、能力和待确认的插件配置操作。loopback 连接另接收 `lifecycle.changed` 当前状态。

Web 和桌面 Client 通过控制通道订阅全局任务队列。服务端用 `tasks.snapshot` 推送所选范围的首屏、活动总数和首屏以外发生变化的任务。重连时重新订阅，历史分页按需读取。在线歌单下载通过 `downloads.progress` 向任务所属用户推送下载摘要，Web 在打开歌单或重连时补读摘要，展开明细时读取逐曲结果。Web 的扫描、插件任务、远程歌单同步以及桌面设置页的扫描和插件任务仍使用 `activity.changed` 按需读取。命令行扫描脚本也通过该通知等待任务结束。第三方扫码授权按平台给出的间隔确认登录结果。

WebSocket 已取代原 `/events` SSE。通知只携带公开状态或资源变更提示，管理员配置及凭据留在对应授权接口。Provider 账号无权限、来源暂不可用、客户端不支持和任务失败应分别呈现。

最小 Web 首次登录用显式 Bearer 凭据和允许的 Origin 校验，取得 HttpOnly 会话 Cookie 与 CSRF token；登录后的状态修改（包括退出）校验会话 CSRF 和 Origin。原生 audio 通过同源 Cookie 访问授权流，无需把凭据放入 URL。详细边界见[联合实施契约](implementation.md#33-同源连接与会话)。

## 5. 播放协商、定位与恢复

各客户端上报实际可用的 codec、container、MIME、传输方式、定位能力及请求的处理效果。Server 选择可交付的来源与输出：兼容且无需处理时直接播放或字节代理；需要兼容处理或 DSP 时使用 Server 插件链输出。播放契约分别接受浏览器的 `htmlAudio` 和原生播放器的 `nativeHttp`，返回描述携带协商后的传输类型。Android 按本机支持的格式上报，详见 [Android 原生播放接入](../android/docs/server-playback.md)。

NCM 由 Server 的内置 `audio.decrypt` 插件解除外层容器，保留内部编码字节；纯解密交付为 `proxy`，需要兼容转码或用户请求 DSP 时再进入处理链并返回 `processed`。`effectiveProcessing` 的 `ncmDecrypt` 项标明服务端解密，不能据此宣称应用了增益等 DSP。内置插件在主进程内通过独立通信流保留版本化 JSON-RPC 控制语义，显式外部模式才使用 stdio；控制面只传任务与资源描述。音频正文走独立、受任务授权约束的私有二进制通道，由 Server 管理取消与回收。Client / Web 只访问 Server 返回的受鉴权播放地址，不直接连接插件数据通道。配置、协议和已验证范围见 [Server NCM 插件](../server/docs/playback/ncm.md)，不由本节扩大其他格式或平台的实现范围。

2026-10-22 音频编解码增量：文件头识别规则、候选扩展名和识别优先级由插件声明，Server 按优先级降序、同优先级按注册顺序轮询。插件输出可声明仍需解码，宿主重新识别该输出并选择下一层；只有插件标记无需继续解码才终止，重复输入和超过八层的链被拒绝。NCM 输出的 MP3/FLAC 会交给下一层 FFmpeg 插件，默认原生模式保留音频字节并结束宿主解码；可选择 32 位浮点或 16 位整数 PCM 输出，实际解码后进入播放处理链。FFmpeg 另外提供显式 MP3、FLAC、Opus、WAV 转码能力，自动解码不递归执行转码。后台指纹仍采用固定的标准化规格，不跟随用户播放设置。该变更不改变源文件及资产身份；客户端继续消费最终协商的播放格式，不直接访问中间 PCM。SDK、资源限制和已实现的插件装配范围见 [Server 编解码链](../server/docs/plugins/audio-codecs.md)。

Web 通过 `canPlayType` 随播放请求报告格式支持。支持 FLAC 且无需处理时，Server 原样交付经结构校验的 FLAC；NCM 保留解封后的内部 FLAC 字节。必要转码以来源资产的音频码率选择目标编码可用范围内最接近的码率，未知时使用默认配置；码率纳入输出配置及表示身份，定位、恢复和缓存沿用该会话配置。Web 播放栏展示源封装、内部编码、发送编码的完整链路，以及发送采样率、码率和声道数，避免混淆服务端传输与浏览器解码输出。

| 播放描述字段 | 语义 |
| --- | --- |
| attemptId、assetId、representationId | 固定本次输入与输出的版本身份 |
| deliveryMode、streamUrl、expiresAt | direct / proxy / processed，短期限定权限的地址及有效期 |
| outputProfile | codec、container、MIME、传输方式、采样率、声道和适用的码率配置 |
| effectiveProcessing | 实际生效的处理链、参数版本与执行端；同一效果不能在两端重复应用 |
| dspExecution | 音效执行端：client 或 server；Web 必须确认 client，服务端跳过音效和声道扩展，仅保留格式所需的兼容适配 |
| seekMode、seekableRange、positionOriginMs | byteRange / timeRestart / none；以毫秒表示可定位的曲目时间范围及输出起点映射 |
| timeline、resumeDecision | 已验证的资产间时间映射引用/版本与可自动续播、需从头播放或不可用的决定 |

Web 的输出布局偏好按稳定 API 访问地址和账号保存在浏览器中，不使用随服务端重启变化的生命周期 `instanceId`，因此服务端重启后仍可恢复已保存的输出设置。

本地/NAS 或需要私密请求头的来源由 Server 交付。直放地址必须允许客户端访问且不泄露账号凭据；短期播放授权仍须限制用户、资源、用途和有效期。原始字节代理只声明实际具备的 Range 能力，上游不支持时不伪造 206。处理后输出不继承原文件的字节偏移、长度或验证器；byteRange 只适用于稳定且可随机访问的输出表示。

timeRestart 定位通过时间请求重新生成输出，客户端加载新的 streamUrl，按 positionOriginMs 和时间映射显示曲目进度；不能把原文件字节偏移应用到转码流。客户端忽略旧歌曲/会话的返回；同会话 seek/recover 串行执行，先确认在途操作返回的 attemptId，再执行合并后的最新定位意图。WS 断线或客户端取消等待不等于撤销已发生的服务端变更，通道不自动重放已发送修改；当前 Web 对未知结果停止自动控制并提示重新播放，业务层如显式重试必须沿用原幂等键。细则见[联合实施契约](implementation.md#32-播放描述与客户端状态)。处理配置变化也必须协商新表示。同源输出重建在曲目时间到新输出的映射已验证且可定位时恢复，不要求该 SourceTrack 已关联 Recording；资产内容变化则必须重新验证时间关系。

播放失败时客户端报告 attemptId、观察到的错误与曲目时间，Server 决定有限的同源刷新或换源。浏览器不必识别上游 URL 过期的具体 HTTP 原因。恢复同时限制同源刷新次数、不同来源数（最多 3 个）及总时间预算；同次故障的重复请求不能不断重置预算。

播放位置以整数毫秒提交，Web 在 seek/recover 请求边界统一取整。浏览器仍可播放已缓存音频，因此没有活动 HTTP 音频连接不代表播放结束；Server 在 `expiresAt` 前保留会话，停止、登录撤销及服务关闭仍释放资源。音频流允许浏览器暂停读取，取消会话或切换尝试仍打断旧连接，具体有效期和资源约束见 [Server 播放恢复](../server/docs/playback/recovery.md)。

跨源自动续播须同时满足：确认同一 Recording；具有绑定两端资产版本且覆盖目标位置的独立时间轴兼容证据；目标输出及处理链支持所需定位。证据需处理前导静音、裁切、编码延迟等差异；同名、相近时长、相同 Recording 或音频指纹相似均不能单独满足条件。满足条件则返回新尝试和新地址，客户端清理旧缓冲并按映射重载，允许短暂中断；条件不满足或定位失败则提示从头播放，用户可取消，不猜测进度。新表示不能续接旧 Range；同源刷新若复用字节状态也须先验证资源未变。

歌词随当前来源与版本重新选择，时序不兼容时不能沿用旧歌词位置；用户配置的歌词偏移单独保留。桌面和 Web 播放器在本地输出端处理淡出淡入。切歌、暂停和进度跳转共用一个默认开启的开关，各场景的时长独立保存，默认 300 毫秒。暂停后继续播放时按暂停时长淡入。具体行为见 [Client 音频设计](../client/docs/audio-processing.md)和 [Web 播放配置](../web/docs/dsp-settings.md)。详见 [跨端播放时序](diagrams/playback.puml)。

## 6. 歌单与任务的一致性

目录刷新和 Web 自动歌词搜索共用按用户保存的歌词来源顺序。默认先找本地内嵌或同名旁置歌词，再依次使用网易云音乐和 QQ 音乐。找到匹配歌词即停止，用户也可以在设置中加入 LRCLIB。[歌词与封面处理](../server/docs/metadata/metadata.md#导入歌词与自动补缺)

聚合歌单按绑定及子歌单的原始顺序展开。曲目条目按曲目及其强制来源去重，两种不同的指定版本可以并列。来源贡献按已确认的 Recording 或具体 SourceTrack 去重，并保留全部出处。同一条目存在多个未隐藏的本地来源时，从这些实际贡献中优先使用手动默认，否则按可用性、码率、文件大小选择；不引入歌单之外的来源，不恢复已隐藏的贡献。重建时重新判断默认来源，必要时发布新快照，已发布的历史快照保持不变。移除一个来源贡献不删除仍有其他出处的条目。界面按固定 revision 分页，使用预期修订编辑；旧任务不得覆盖新发布状态。

远程歌单不提供一致快照版本时，分页完整也不能证明缺失项已删除。Server 先将其标记疑似移除，经后续完整同步或独立查询复核后移除贡献；Client / Web 显示同步中、疑似移除、stale、lastSuccessAt 和失败原因。失败或不完整同步保留上次有效内容，NAS 离线不清空音乐库。

隐藏默认针对整首 Recording 的全部来源，也允许只隐藏某个 binding/原 entryId 对应的出处。隐藏绑定持久身份，不绑定重建的展示行；未匹配条目先按 SourceTrack 保存意图，后续关联/拆分也应保留用户原始目标，无法唯一确定时提示确认。隐藏和聚合规则保存在本地，循环歌单引用应明确报错。用户可将可写的网易云歌单关联到自建歌单或“我的收藏”，关联后新增的网易云曲目进入追加队列。内部快照、代次及恢复实现见 Server 文档。

## 7. 本地连接、退出与升级协作

同一局域网中的客户端可通过 mDNS/DNS-SD 浏览 `_musicfs._tcp.local.`。Server 用 SRV 公布实际监听端口，TXT 的 `api=1` 和 `scheme=https` 表示接入版本和协议。`origin` 指定部署允许且证书覆盖的访问地址，例如 `https://music.home.example:8443`。局域网 DNS 负责把该名称解析到 Server。服务退出后撤销发布。仅绑定回环的实例继续只供本机使用。

Android 手机、平板与 TV 在登录页浏览实例，用户选择后可核对或修改地址，再显式提交登录凭据。手动地址适用于外网、跨子网或组播不可达的网络。两种入口共用 TLS、实例校验和登录流程。

| 连接模式 | 跨端行为 |
| --- | --- |
| managed-local | Client 可启动配套 Server；可连接已经运行的兼容实例，但不能改变其原始启动归属 |
| external-local / service | 只连接本机独立部署的 Server，不自动启动、提权或接管服务 |
| remote | 连接指定远程 Server，不启动本机 Server |

连接须验证 MusicFS 实例身份、协议兼容性并完成授权握手，不能只看 HTTP 200；端口冲突及不兼容版本应显示明确状态。多个 Client 并发启动不能产生多个占用同一数据目录的 Server。客户端启动器内部实现见 [Client 内部架构](../client/docs/architecture.md)。

Server 保留实际启动归属并维护经鉴权的 Client 租约。Client 通过 WS request 显式申请、续期和释放；30 秒租约建议每 10 秒续期，连接 ping 不自动续租。断线宽限由原租约期限决定，重连不复活过期租约。随 Client 启动的实例在最后一个有效租约结束后优雅退出；Client 崩溃由租约超时处理，启动后始终未建立租约的失败启动也应有界回收。独立启动的实例保持运行，不因 Client 连接/退出改变归属。进入 draining 后拒绝新的租约和续租，停机状态通知尽力发送，客户端最终以连接状态和重新发现结果确认实例；持久化和写任务收尾细节见 Server 文档。桌面 Client 已可连接现有 Server，本机托管模式的启动器与租约管理仍待实施。

升级 managed-local Server 需协调所有活动 Client、优雅停机、数据迁移准备与新版就绪；失败保留可恢复入口，不直接覆盖运行中的程序。不兼容的独立 Server 由其部署方式管理升级，Client 仅提示，不能自动停止或接管。详见 [Windows 连接与生命周期](diagrams/windows-launch.puml)。

## 8. 共同权限与验收

用户只看到自己可访问的来源、歌单、内容对象和会话；共享录音元数据不能暴露其他用户的私人文件。客户端及无关插件不获得服务端托管的 Provider / Scraper 账号密钥；平台要求的客户端授权流程遵循第 2.1 节的最小范围约定。歌曲引用或本地控制请求也不能跳过 Server 授权。面向浏览器的连接采用明确的来源许可与适当的会话保护，远程访问配置鉴权和安全传输，日志不得泄露带授权的 URL 或请求头。

跨端验收按以下顺序推进；单端技术选型、插件接口与内部验证清单在各仓库维护。

1. 本地/NAS 来源发现、音乐库展示、固定修订歌单和原流播放；未知码率/摘要也能按权限播放。
2. 独立 Scraper 的预览、人工选用、上传/编辑与歌词/封面读取；默认原文件不变，显式安全写回后来源身份和歌单仍有效。
3. 在线来源按平台分阶段交付；网易云、QQ 音乐、Apple Music 插件各自必须通过第 2.1 节的平台账号登录验收，不能以一个平台通过替代另外两个。推荐能力单独验证；聚合多出处、保守移除、隐藏和凭据失效状态一致。独立在线 Scraper 分别验收，不依赖在线 Provider 同时上线。
4. NFS、SMB 各自完成真实 NAS 扫描、播放、定位、离线恢复与根身份变化验收；Bilibili 分别验证免登录视频音轨、公开收藏夹、多 P 展开和音频区曲目/独立歌单，可选私有功能另验账号隔离。不得以挂载 NAS 或一个 B 站端点成功代替全部插件验收。
5. Server 处理输出在真实 Web 环境播放和按时间定位，桌面原生能力单独协商；DSP 不重复，跨源无法证明时间轴兼容时提示重播。
6. 多 Client 启停、崩溃租约回收、独立 Server 保持运行、remote 无本机启动，以及不兼容版本的可恢复升级流程。
7. Android 手机与平板调整窗口后保持播放，TV 仅用遥控器完成选曲与切歌。[Android 设备验收](../android/docs/device-experiences.md)
