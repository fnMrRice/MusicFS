# C/S 插件职责与扩展边界

状态：架构细化；2026-10-21。本文定义跨端约束，记录 Server 内置插件的主进程实现及其他待实施扩展，不新增公共 API。精确接口归各实现仓库；事实基线见[总体架构](architecture.md)、[Server 架构](../server/docs/architecture.md)和 [Client 架构](../client/docs/architecture.md)。

## 1. 当前架构是否支持

支持继续扩展，但当前没有两端通用的即装即用插件系统。Server 官方内置插件全部编译到 Go 主进程，包括来源、解码、Scraper、DSP、SQLite 以及四类媒体算法；各实例与任务仍有独立配置、上下文和账号边界。只有显式选择的外部进程配置才启动插件程序，普通插件使用 `execution: process`；FFmpeg、ffprobe、fpcalc 等外部工具按任务受控执行。宿主固定校验支持的身份和能力，新增插件 ID 仍需注册和适配。

桌面播放器采用 Rust/egui。以下 Rust Plugin Host 与 C ABI 属于后续规划。原生插件直接加载动态库，在同一原生宿主进程中运行，不采用插件 worker 或独立音频引擎进程。Windows 使用 DLL，其他目标平台使用 dylib/so。Client 不提供插件卸载，所有已加载库保留至进程退出，插件启停、更新和回滚统一重启生效。声明式主题不必包装为 DLL。

以下范围不能仅安装一个包就获得支持，实施前须先补契约或报告验证限制：

| 范围 | 当前限制 | 先完成的工作 |
| --- | --- | --- |
| Server 新插件 ID，包括同属 Provider 的适配 | 部分 Host 固定认可内置 ID/能力，并非读取任意 manifest 即注册 | 先补通用注册、配置与分派机制；核对方法覆盖，缺字段在 Server 修订 SDK 与样本 |
| NFS/SMB 直连、Bilibili/其他在线音频 | 现有播放资源通道仍有本地资源假设 | 扩展受授权资源读取、资产建档、版本/定位证据，不返回 NAS 凭据或任意代理 URL |
| Server 新分析、标签、评分、内容变换或输出存储实现 | 已有四类算法的进程内接口；当前严格协议与注册表没有通用的任意角色机制 | 复用已验证接口或先补契约；新实现须编入 Server 并验收，不把接口存在当任意第三方加载能力 |
| Server 音频节点组合 | 内置增益、EQ、压缩器、混响与独立声道转换；有状态定位从曲首重建，支持 stereo/5.1/7.1 输出；外部 DSP v1 仍仅无状态双声道 | 任意拓扑、追加尾音、前视延迟、空间上混与检查点须继续扩展并验收 |
| Client 原生动态库 | 宿主、C ABI、安装包与平台加载尚待实施 | 按 C0—C3 实现加载、生命周期及最小 DSP 插件，C7 验证制品 |
| Client 原生播放协商 | 已通过 `nativeHttp` 验证 Windows 上的 MP3、FLAC 和 WAV 播放 | 新增格式须验证解码与设备输出后再声明支持 |
| Client 原生插件故障隔离 | 同进程不能提供崩溃/内存破坏隔离或安全强停 | 接受宿主故障边界，验证受信任插件、可恢复配置和下次启动禁用；不回退为插件子进程 |
| Server 内置插件故障隔离 | 主进程共享地址空间，取消是协作，不能安全强杀单个插件 | 验证上下文、租约与收尾；进程崩溃可能影响整个 Server，只有显式外部模式另验收进程回收 |

如果后续需求必须隔离恶意本机代码，或必须在插件卡死后强杀插件而保持 Client 运行，则与当前单进程约束冲突，应先向用户说明，不能静默改回多进程。普通接口缺失按已标明的设计增量处理，不宣称当前已经可用。

## 2. 尽量插件化的分工

“插件”指通过有版本契约替换实现的能力，不要求把每个类、线程或数据库表单独打包。一个插件包可以声明多个兼容能力，但能力、实例和配置分别标识；插件之间不直接链接对方私有接口，依赖由宿主解析，禁止循环依赖。

| 能力 | 所属端与插件方向 | 宿主保留的责任 |
| --- | --- | --- |
| 本地/挂载 NAS、直连 NAS、在线平台 | Server Music Provider；平台登录与远程歌单适配归对应 Provider | 授权、身份建档、扫描完整性、同步发布、用户与账号隔离 |
| CD 专辑、ASMR、电台 | Server 内容类型插件，声明独立作品库入口、作品资料及包内顺序 | 文件授权与稳定身份、各库查询范围、按专辑保存普通曲目展示选择、统一播放 |
| 歌词、封面、标签候选 | Server 独立 Scraper；本地提取与各在线来源分别适配 | 候选选用、人工锁定、Media Store 发布、写回审批与恢复 |
| 解密、解复用、解码、DSP、编码与封装 | Server 音频插件；Client 按需要提供本机解复用、解码与 DSP | 链路选择、缓冲、时钟/映射、定位和实际效果报告 |
| 音频分析、标签格式、匹配评分、内容变换 | Server 主进程内置插件；当前实现 Chromaprint、FLAC、标准评分、PNG/JPEG 缩略图 | 证据版本、授权读取、人工排除、Recording 关联、原件替换、结果发布与续播决定 |
| 本机设备后端、歌词呈现、系统媒体控制 | Client 可替换的原生能力；新增 SDK 类型分阶段开放 | 唯一输出时钟、窗口/设备归属、命令验证、退出及回调释放 |
| 主题、可选外部控制 | Client 声明式主题、原生控制插件 | UI 数据接口、PlayerCore 状态与授权命令；普通控制不授予安装权限 |
| 数据库后端 / 备份 | Server 可信 Backend；数据库插件负责主库与实例状态库的建库、Schema、迁移和原子操作；默认内置 SQLite，也可选择原生 PostgreSQL；独立 SQLite Worker 仍可选 | 业务数据与事务契约、启动锁、生命周期、一致性清单、对象引用、密钥和恢复判断 |

各端插件类型及精确扩展契约分别见 [Server 插件架构](../server/docs/plugins/plugin-architecture.md)和 [Client 插件能力](../client/docs/plugin-capabilities.md)，不能把本表中的类别名直接写入现有 wire 协议。Web 继续按 Server 能力展示，不安装 C++ 插件，不读取 DLL，也不与 Server 插件通道直接通信。

Server 的容器解码插件可提供音频流和独立有界附件，由宿主汇集各解码层附件并保持读取生命周期。NCM 外层封面由现有 NCM 插件读取，再由通用本地 Scraper 验证并生成容器来源候选；音频标签封面仍由 Scraper 提取，缩略图仍由内容变换插件处理。无需新增专用 NCM 封面插件，也不把外层封面重写进 MP3/FLAC。授权、来源及资产版本、候选选用与发布仍归宿主；接口和真实文件验收范围见 [Server NCM](../server/docs/playback/ncm.md)。

重复识别插件负责识别规则、评分、参数和设置页面声明。Server 负责后台任务、候选存储及资产和权限复核；人工关联、解除、排除、审计与按 Recording 聚合曲库始终属于 Server 自身，不依赖识别插件启用。插件设置采用声明式控件和已注册动作，Web 通用渲染按钮、文字/数值输入、开关及下拉选择；不把任意 URL 或脚本作为设置动作。当前接入标准录音匹配插件，其他插件须实现对应 SDK 并由宿主注册，不能把设置渲染能力描述为任意第三方插件加载。

以下职责保持内核模块：Server 的会话鉴权、API/事件协议及其 Schema 校验、稳定身份、业务数据与事务契约、人工结果保护、授权流网关和任务发布；Client 的 PlayerCore、Server 会话适配、安装/加载管理、配置提交、缓冲所有权、生命周期和受控启动器。可信存储后端负责具体数据库结构、初始化和迁移，成功后才返回可用后端；宿主取得数据锁后调用写入初始化，配置预加载只读且不建库。普通算法插件不能直接提交核心状态。外部 DSP 与持久化使用各自专用契约，细节见 [DSP 插件](../server/docs/plugins/dsp-plugins.md)和[存储插件](../server/docs/plugins/storage-plugins.md)。

## 3. 两端运行和语言选择

| 项目 | Client | Server |
| --- | --- | --- |
| 原生插件执行 | 单一 Rust 原生宿主进程内的动态库 | 官方内置实现均在 Server 主进程；显式外部模式才使用独立进程 |
| 边界 | 版本化 C ABI，固定宽度数据、不透明句柄、明确释放方 | 内置 Go 接口或独立内存流上的原协议；外部模式用 stdio，媒体保留任务授权二进制通道 |
| C++ 构建产物 | CMake/C++23 动态库及运行依赖 | 未来内置桥接必须同进程，尚待实现；可执行插件仅用于显式外部模式 |
| 现有语言 | 界面、会话适配与播放核心均使用 Rust | Go 宿主与插件实现保留，外部工具无需改写 |
| 故障范围 | 越界访问、崩溃或卡死可能影响整个 Client；超时不能撤销本机机器码执行 | 内置插件故障可能影响整个 Server，取消是协作；仅外部模式可回收插件进程，仍不等于 OS 权限沙箱 |
| 可复用对象 | 算法源码、测试向量、媒体格式语义 | 同左；SDK、生命周期和制品独立版本化 |

使用 C++ 的理由应明确到插件：例如现有原生库封装、DSP 算法或平台媒体 SDK。每个采用 C++ 的自有插件/适配层统一遵循 [CMake/C++23 规范](native-plugins.md)，不以 C++23 推导 ABI 通用性。第三方 C 库或原有工程保持其自身构建机制，由受控依赖集成；不为满足标准标记而改写上游源码。

## 4. 共同配置、能力与版本规则

1. 区分包 ID/版本/摘要、宿主 SDK/协议、角色接口、实例 ID、配置修订、装载代次和任务/播放代次。显示名不是身份；同包多角色不隐式共享账户或机密。
2. 包声明仅描述候选能力。目标平台和版本匹配、依赖可用、初始化成功并取得必要授权后，才发布运行能力。期望启用、已发现、待配置与已就绪分别呈现。
3. 新旧协议兼容按精确 Schema 与校验行为判定。当前 Server 严格解码不能假定未知可选字段总被忽略；需要配套升级时明确顺序、支持组合及回退范围。
4. 配置提交检查预期修订。热参数与需重建的参数分开，插件只提出配置结果，由宿主发布有效修订；失败保留原配置/原活动版本。凭据不进入包、主题、日志或普通导出。
5. 任务固定插件版本及配置摘要。Server 源资产或处理链改变输出表示时，重新协商并返回新 attempt/representation，Client 清理旧缓冲；Client 纯本地 DSP/设备图变化更新本机处理代次、图、缓存身份和效果快照，不要求 Server 重建不变的音频流。C/S 两端按有效处理链避免重复增益、EQ 或变速。
6. Server 停用只保存开关，重启后生效；当前业务准入、Worker 和已有租约保持，配置重建仍按自身契约排空。Client 停用只保存下次启动的期望开关并显示待重启，不立即改变当前运行能力；重启时不加载已停用插件。Client 更新/回滚同样下次启动激活，不提供包卸载或运行中卸载 DLL。两端正常任务取消都保留必要完成回调，不能把取消堵在未返回的串行业务调用之后；停用不删除音乐库、歌单、人工内容或实例数据。

Client 原生插件与 Server 内置插件都能访问各自宿主的地址空间。受限 API 与清单用于防止误用和记录约定，不能声称隔离恶意插件；安装与更新需明确可信来源。Server 的账号、用户、实例、资产版本与授权检查继续保护业务接口，同进程不允许不同实例共享凭据或绕过人工锁；OS 沙箱能力仍须按平台单独验证。

Server 四类内置实现分别位于 `plugins/analysis/chromaprint`、`plugins/tags/flac`、`plugins/matching/standard`、`plugins/transform/thumbnail`，接入 `fingerprintworker.Extractor`、`sdk/tagformat.Format`、`candidates.Scorer`、`sdk/contenttransform.Thumbnailer`。它们各有发行版本，和协议、算法、配置版本分别管理；升级编译内实现仍需重新构建和升级 Server。BPM、调性、ID3/MP4、歌词对齐及第三方评分加载不属于当前实现。

## 5. 实施顺序与验收

| 顺序 | 工作 | 完成证据 |
| --- | --- | --- |
| A | 梳理现有方法/能力与新增接口，分别形成两端 SDK 草案；Server 将按内置 ID 的注册与分派改为版本化注册/能力契约 | 每项有宿主、输入/输出、资源权限、取消与版本策略；身份与可信来源校验保留，不改变现有 wire 名称含义 |
| B | Client 最小动态加载链；Server 按需要设计内置 C++ 桥接或显式外部 IPC 插件 | CMake/C++23 干净构建；正确产物完成对应 C ABI/IPC 往返，坏版本与缺依赖拒绝；不以外部进程替代内置同进程要求 |
| C | 安装、能力注册、配置、停用与更新 | Client 动态包按设计不重编译宿主且启停/更新/回滚重启生效；Server 官方内置实现随 Server 构建升级，外部包仅在已支持契约下显式配置；失败可恢复 |
| D | 扩展来源/媒体算法/设备等能力 | 逐角色验收正确结果、时钟、背压与身份；真实资源失败不破坏已发布状态 |
| E | C/S/Web 联合回归和发行 | 原流、处理流、seek/recover、配置/能力变化和旧 Web 兼容；制品支持矩阵与证据一致 |

最小故障矩阵包括：错误 target/ABI、未知必需能力、半途取消、回调迟到、插件拒绝退出、错误配置、依赖缺失、崩溃后重启、更新失败和恢复旧包。同进程插件崩溃注入在可丢弃测试运行中验证下次启动恢复，不能要求主进程存活来证明隔离；Server 只有显式外部模式验证 Worker 崩溃后的回收和无关实例继续服务。内置实例独立取消不等于强制终止失控代码。

Client 与其余扩展仍按设计实施；Server 的内置运行、四类算法、DSP/持久化实现及验证在对应仓库维护，工具替身测试不证明真实音频工具或平台账号已验收。实现提交完成后再由主仓库记录子模块版本。运行边界见 [PlantUML 源图](diagrams/plugin-boundaries.puml)。
