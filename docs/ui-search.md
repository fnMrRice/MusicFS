# 搜索页设计

状态：设计草案 v0.3，2026-10-10，待确认，未实现。继承[共享布局](ui-design.md)与[跨端架构](architecture.md)；与曲目列表内查找不同，这里负责用户可访问来源的独立搜索。

## 1. 页面布局

左侧搜索入口高亮，品牌 Banner 与“我的账号”区固定，中间导航和歌单整体滚动。“我的”包含我的收藏、最近播放，“歌单”包含歌单列表，分别支持展开或收起。顶部保留返回、搜索标题以及纯图标操作：设置、换肤、浅色竖线、迷你模式、最小化、最大化、关闭；按钮名称通过 tooltip 展示。底部全宽播放栏保持固定。

右侧从上到下安排较宽的搜索框与搜索按钮、来源选择、结果类型、结果工具栏和结果内容。搜索框属于搜索页内容，不移动到全局窗口标题栏。结果区滚动接近底部时自动追加内容；不设分页器或固定加载计数栏。

## 2. 搜索前与提交

未输入时，搜索框占位为“搜索曲目、歌手、专辑或歌单”；下方可展示当前用户本机保存的最近搜索，支持单条删除与清空。无历史时只提示输入关键词，不虚构热门搜索。

Enter 或点击搜索按钮提交，空白词不提交。框内清除按钮只清空输入并返回搜索前状态；历史记录点击后可直接发起搜索。输入法组合输入期间不因 Enter 误提交。未提交的输入不替换当前结果标题。

搜索中保留查询词与来源条件，用骨架展示等待状态；新查询或切换来源后，忽略旧请求结果，避免旧内容覆盖新查询。返回页面时恢复查询、来源、结果类型、有效游标与滚动位置；缓存过期时提示刷新，不伪装成最新结果。

## 3. 来源与结果类型

| 控件 | 设计 |
| --- | --- |
| 来源选择 | 全部来源及实际可访问、支持搜索的实例；实例过多时折叠进更多来源选择器 |
| 曲目 / 专辑 / 歌手 / 歌单 | 四类独立搜索结果，默认曲目；准确计数显示在对应标签旁，未知时不虚构数量。单一来源不支持某类别时保留标签并明确提示不支持，不将其误报为空结果 |
| 歌手、专辑关键词 | 既可匹配曲目字段，也可在歌手或专辑类别中检索独立对象；不能仅用曲目结果推断完整歌手/专辑结果 |
| 仅可播放 | 作用于当前曲目结果；状态未知不能视为可播放，过滤及计数须覆盖完整结果集合 |
| 排序 | 默认相关性（来源返回的顺序）；单一来源支持时才提供曲名、歌手等其他排序 |

“全部来源”按来源分区保留各自排名及出处，不强行比较不同平台的相关性分数，不自动合并同名歌曲、专辑或歌手。各来源独立维护游标和加载状态，接近分区末尾才请求下一批，避免混用游标；选定单一来源后显示对应表格或卡片连续列表。来源切换保留已提交关键词和结果类型，清空旧游标，从首批结果重新获取；结果类型不支持时明确提示并提供切回曲目入口。

## 4. 结果呈现与操作

曲目表格显示封面、曲名、歌手、专辑、来源、时长，以及收藏与更多操作。查询词可用低强度强调色突出，避免与整行播放状态混淆。Live、Remix 等版本信息保留，当前播放行按具体来源曲目身份判断。

曲目表格最左侧常驻复选框，表头全选范围为点击时已返回的当前来源结果，tooltip 说明范围；新追加条目不自动选中，部分选中显示中间态，不显示“批量选择”按钮。未选择时显示“播放结果”“加入队列”，作用于完整当前来源查询结果，须有完整结果队列能力，不支持时明确提示。选择后显示已选数量及加入队列、添加到歌单、收藏、取消选择。复选框不触发播放，追加保留已选项；变更查询条件清空选择。不可用条目跳过并说明。行菜单提供立即播放、下一首播放、加入队列、添加到歌单与详情；不可用项给出原因。

专辑结果为方形封面卡片，显示专辑名、歌手、发行年份及来源；点击进入专辑详情和曲目列表，未知年份显示“—”。歌手结果为圆形头像卡片，显示歌手名与来源；点击进入歌手详情，查看该来源支持的专辑与曲目。两类结果沿用当前查询与来源，滚动时动态加载；切换类型后从首批开始。卡片本身打开详情，不直接播放全部；对象使用来源实例与稳定标识定位，不根据同名对象自动跨来源合并。缺少封面或头像使用统一占位。

歌单结果使用封面卡片，显示名称、创建者与来源；点击打开曲目页，不自动导入或绑定。用户明确选择导入或绑定后才加入歌单库，不自动写回平台。

## 5. 动态加载与状态

复用[曲目列表动态加载规则](ui-tracks.md)：接近末尾自动请求下一批，不显示页码、跳页、加载计数或加载更多按钮。加载中在结果末尾短暂显示进度，失败保留结果并提供重试，确认结束后停止追加。搜索查询、来源、类型、筛选或排序改变时作废旧请求并从首批开始。追加不改变当前播放和队列。

直接使用 Server 返回的来源游标和结束状态，不猜测游标或总数。准确计数可展示在类型标签，未知时只显示类型名称；不以已返回几条当作完整结果数。多来源仍需分别处理失败、结束和过期，不把单个来源的结束当作整体完成。

无结果时展示关键词、来源范围与清空条件入口；单一来源失败显示原因与重试。多来源部分失败时仅标记失败来源并提供单独重试，其余结果可继续操作；账号权限不足、来源不可用与不支持搜索分开呈现。整体失败不能展示为“没有找到”。

以上为目标交互。曲目、专辑、歌手、歌单四类检索、独立对象详情、收藏、分页及排序均须由 Server 与 Provider 评估支持范围；接口和能力声明由 Server 拥有并同步共同契约，不将设计图视为现有能力。
