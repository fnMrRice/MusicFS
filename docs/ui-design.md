# MusicFS 前端 UI 设计

状态：布局草案 v0.4，2026-10-10；待用户确认，不代表已实现。先确认宽屏布局与导航，颜色、图标和完整交互细节后续定稿。

## 1. 范围与依据

遵循[跨端架构](architecture.md)，在本仓库维护桌面 Client / Web 的共享布局。端内实现与技术选型仍由各实现仓库负责。本稿不修改接口或扩大当前最小 Web 的已实现范围。

参考用户提供的音乐播放器截图：左侧导航与歌单，右侧主内容，底部全宽播放栏。搜索为左侧独立入口。左侧顶部品牌区（Banner）与底部“我的账号”固定，中间导航和歌单整体滚动。顶部使用纯图标，依次为设置、换肤、分隔线、迷你模式、最小化、最大化、关闭；用户菜单仍保留设置入口。

## 2. 整体布局

![整体布局与用户菜单](prototypes/frontend-layout.salt.png)

[可编辑 PlantUML Salt 源文件](prototypes/frontend-layout.salt.puml)。图中用户菜单处于展开状态；实际为覆盖浮层，不挤压歌单列表，不常驻显示。

| 区域 | 内容与行为 |
| --- | --- |
| 左侧品牌区 | MusicFS 标识 / Banner；固定，不参与滚动 |
| 左侧滚动区 | 搜索、推荐、曲目列表、歌单管理，以及可折叠的“我的”“歌单”分组，共用一个纵向滚动容器；位于品牌区与用户区之间，不另设分组内部滚动条 |
| 左侧用户区 | 头像、我的账号、右侧三点；固定在播放栏上方，独立于滚动区，始终可见 |
| 右侧顶部 | 固定工具栏，包含返回、页面标题，以及靠右的设置、换肤和窗口控制图标组 |
| 右侧内容 | 根据当前入口显示对应页面；在顶部工具栏下方独立滚动 |
| 全窗口底部 | 当前曲目、封面、歌手、来源、播放控制、进度、音量和辅助按钮；始终可见 |

建议宽屏侧栏约 240 px、播放栏约 96 px，右侧使用剩余空间；尺寸为待确认建议，Salt 图不作为像素规格。窄屏与移动端布局另行设计。

“我的”分组包含“我的收藏”“最近播放”；“歌单”分组包含用户歌单列表，标题右侧保留新建按钮。两个分组分别支持展开和收起，默认展开；点击标题或箭头切换，并记住当前用户在本机的展开状态。新建按钮不触发折叠。收起分组不切换右侧页面、不影响播放，当前页面所属分组仍有选中提示；键盘可聚焦分组标题并用 Enter / 空格切换，提供展开状态的无障碍语义。固定账号区不参与折叠。

## 3. 页面切换

| 左侧选择 | 右侧页面 | 主要内容 |
| --- | --- | --- |
| 推荐 | 推荐歌单 | 按来源分区、歌单封面网格、刷新；点击卡片进入歌单曲目页 |
| 搜索 | [搜索页专项设计](ui-search.md) | 搜索输入框、来源筛选、曲目/专辑/歌手/歌单结果切换与动态加载；搜索框不放在全局顶部 |
| 曲目列表 | [曲目列表专项设计](ui-tracks.md) | 分类浏览、组合筛选、排序、批量操作与曲目行菜单 |
| “我的”中的我的收藏 / 最近播放 | 对应曲目列表 | 展示收藏或播放记录，不因折叠侧栏分组清空内容；能力按实际支持展示 |
| “歌单”中的某项 | 歌单曲目页 | 封面、名称、来源/同步状态、播放全部、曲目列表及更多操作 |
| 歌单管理 | 管理页 | 新建、导入/绑定、重命名、聚合规则、同步状态等入口；具体操作待细化 |
| 顶部设置 / 用户菜单 → 设置 | 同一个设置页（暂定在右侧） | 连接、来源与账号、播放等分组；按权限和端能力展示 |

返回操作恢复上一个页面及其滚动位置；切换页面保留播放状态与队列。点击推荐歌单只查看，不自动导入或绑定。

## 4. 顶部操作、用户菜单与播放栏

顶部工具栏在右侧内容滚动时保持可见。设置位于换肤左侧；迷你模式紧邻最小化左侧，替代原“小窗”命名。换肤与迷你模式之间增加间距，并放置一条低对比度浅色竖线，将应用设置与窗口控制分组。建议组内间距 8 px、分隔线两侧各留 20 px，最终尺寸随视觉设计调整。

设置、换肤、迷你模式均只显示图标，不常驻显示文字。鼠标悬停约 400 ms 或键盘聚焦时显示 tooltip，名称分别为“设置”“换肤”“迷你模式”；按钮具有同名无障碍标签，移出或按 Escape 关闭提示。最小化、最大化/还原、关闭使用相同提示规则。Salt 图中的文字是图外说明，不作为常驻按钮标签。

换肤打开主题选择浮层；迷你模式为迷你播放器入口，具体窗口方式与各端支持范围待验证，不预设为浏览器画中画；设置进入与用户菜单相同的设置页。桌面窗口控制由宿主提供，Web 按实际能力展示，不模拟无效的窗口操作。能力不支持时清楚说明原因，不展示成可用功能。

点击用户名右侧三点，或右键用户区，打开同一个菜单；默认包含设置与退出登录。菜单优先向上展开，空间不足时调整位置，不被侧栏滚动容器裁切；滚动侧栏时关闭菜单。点击外部或按 Escape 关闭；三点按钮支持键盘操作。右键范围暂定为用户区，不覆盖曲目行等区域自己的菜单。

播放栏左侧放封面与曲目信息，中间放播放模式、上一首、播放/暂停、下一首和进度，右侧放收藏、歌词、队列、音量与更多。辅助按钮是首轮建议，最终取舍待确认。

未选择曲目时显示“尚未播放”，禁用无效控制；加载、缓冲、播放失败应有明确状态。不可定位的曲目不允许拖动进度。来源切换及恢复遵循架构约定，不能保证续播时提示用户从头播放。

### 4.1 平台账号入口

设置页的“来源与账号”分别展示网易云、QQ 音乐、Apple Music 的平台账号卡片，显示平台名、所属来源实例、账号显示名及未登录/已登录/已过期状态，提供“登录网易云”“登录 QQ 音乐”“登录 Apple Music”、重新授权和退出对应平台账号的操作。这是三个插件的必需登录交互，尚未实现时明确标注，不展示可用的空操作。

根据插件已验证的方式显示扫码、授权跳转或其他登录步骤；等待过程中允许取消，超时、授权拒绝、网络失败分别给出原因与重试入口。完成后刷新该来源的账号状态及能力；需要会员或内容权限时单独说明，不能用“已登录”代替“可播放”。具体流程遵循[平台账号登录约定](architecture.md#21-在线平台账号登录)。

左下“我的账号”及用户菜单的“退出登录”指 MusicFS 会话；平台卡片的“退出平台账号”只解除所选平台账号在 MusicFS 中的绑定，文案必须带平台名，避免混淆。平台登录过期不会把用户退出 MusicFS，也不影响其他平台账号。

## 5. 数据与能力边界

- 推荐和搜索只展示实际具备能力且用户可访问的来源；未接入推荐时展示说明和可用的音乐库入口。
- 各来源保留排序与出处；部分来源失败不遮挡其余内容，过期结果标明状态并提供重试。
- 推荐可见不代表可播放；曲目不可用时说明登录、权限或来源故障等原因。
- 歌单同步中、失败、疑似移除与上次成功时间可辨识；失败保留上次有效内容，编辑本地规则不自动写回平台。
- 图中歌单、数量与歌曲均为示例，不宣称平台推荐或账号功能已完成。

2. 搜索入口打开右侧独立页面、设置也在右侧打开，是否符合预期？
3. 播放栏按钮取舍，以及下一轮是否沿用参考图的深色风格。

确认后再细化搜索、歌单曲目页、歌单管理与设置的页面线框，以及空白、加载和错误状态。

