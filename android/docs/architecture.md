# MusicFS Android 客户端架构设计

本文同时描述已落地的第一版与后续设计。当前可用范围及构建方式见[工程入口](../README.md)。四种设备使用一个 Android 工程，按手机／平板／TV 与 Wear OS 输出两个应用制品。每台设备直接连接已部署的 MusicFS Server，并在本机播放。当前工程使用 Kotlin、Jetpack Compose、OkHttp 与 Media3，格式支持、系统行为和耗电需用实际设备验证。[跨端职责与协议](../../docs/architecture.md) · [跨端组件图](../../docs/diagrams/components.puml)

## 构建与分发

| 构建目标 | 入口与交付方式 | 使用的界面 |
| --- | --- | --- |
| 手机／平板／TV | 一个 Android 应用模块。清单分别声明普通启动入口和 `LEANBACK_LAUNCHER` 电视入口，触屏与 `android.software.leanback` 均为可选特性。 | 手机和平板加载同一套自适应页面，电视加载可用方向键完整操作的页面。 |
| Wear OS | 独立应用模块，声明手表硬件和独立运行。若通过 Google Play 发布，与主应用共用应用 ID，手表制品单独上传与更新。 | 在手表完成 Server 配置、鉴权、曲库浏览和播放，使用表端的网络、存储与音频输出。 |

拆分构建目标后，手表只需打包表端界面与共享库。两种制品可分别测试和发布。入口与分发约束见 [Android TV 应用指南](https://developer.android.com/training/tv/get-started/create)和 [Wear OS 打包指南](https://developer.android.com/training/wearables/packaging)。

## 模块与状态归属

两个应用入口位于 `src/app/main/` 和 `src/app/wear/`，共用 `src/connection/` 与 `src/playback/`。当前触屏与电视界面在主应用内，表端界面在手表应用内，曲库分页由连接模块负责。下表给出完整能力的职责分工。

| 规划位置 | 职责 | 状态归属 |
| --- | --- | --- |
| `src/app/main/`、`src/app/wear/` | 声明各自的启动入口、播放服务及系统权限，选择对应设备界面。 | 应用级连接配置以设备为单位保存。 |
| `src/ui/handheld/`、`src/ui/tv/`、`src/ui/wear/` | 展示相同的曲库、歌单和播放状态。触屏页面响应窗口变化，TV 管理焦点，Wear 使用小屏导航。 | 各入口持有选中项、滚动位置、焦点等界面状态。 |
| `src/library/` | 按授权读取曲库与歌单，封装分页、修订与失效刷新。向三套界面提供同一份查询语义。 | Server 持有曲库、歌单与来源权限。设备缓存以实例和账号隔离。 |
| `src/connection/` | 对接 Server 契约，校验实例、管理登录和控制通道，为播放层提供受鉴权的媒体读取。 | 每台设备持有自己的 Cookie、CSRF 和连接。注销或切换账号使对应请求失效。 |
| `src/playback/` | 管理本机队列、当前曲目、播放命令、服务端播放尝试与 Media3 播放器。 | 每台设备的播放服务唯一持有活动队列和播放器。服务端描述决定可读取的音频表示及允许的定位方式。 |

UI 经曲库模块查询内容，经 `MediaController` 访问本机播放服务。播放和曲库模块依赖连接模块，连接模块不依赖 UI。手机和手表即使登录同一账号，也分别建立会话与队列，手表切歌只改变手表的播放。[Android 组件图](diagrams/components.puml)

## 本机播放服务

首版支持从分页曲库点播、切换至另一首曲目、暂停与继续。系统媒体会话开放播放／暂停和只读元数据命令。下文涉及的完整队列、进程回收后的恢复、定位及故障续播是后续设计。

用户在歌单里选曲时，界面将曲目标识与队列交给播放服务。服务经 WebSocket 创建服务端播放会话，把返回的音频描述交给 HTTP 数据源，再由本机 ExoPlayer 解码输出。进度以实际播放器时钟和服务端返回的曲目时间映射为准。曲目切换、失败恢复和定位统一由播放服务处理。[Server 接入与播放](server-playback.md)

`MediaSessionService` 持有播放器和 `MediaSession`，播放期间按 Android 的媒体播放前台服务规则运行。触屏控件、TV 遥控器、锁屏和耳机按键通过同一命令入口操作。媒体会话对外公布的切歌和定位能力随队列与服务端描述更新。播放层适配 Media3 的 `Player` 命令，例如 `timeRestart` 定位先请求 Server，再让 ExoPlayer 加载新流。服务根据音频焦点与输出设备变化暂停或恢复。手表耳机断开时暂停，重新连接后由用户继续。[Media3 后台播放](https://developer.android.com/media/media3/session/background-playback)

退出页面、平板分屏或手表熄屏时，播放中的服务继续工作。进程被系统回收后，只保留恢复所需的曲目标识、队列顺序和上次确认的曲目位置，并按实例和账号隔离。用户选择继续时重新鉴权、确认资源与可定位范围，再建立有效播放尝试。已过期的流地址或旧尝试不能作为恢复依据。

## 实施与验收顺序

1. **验证原生协议。** 在 Server 定义原生播放器能力与输出传输，使用真实 Server 从 Android 播放一首本地曲目，覆盖原流、处理后输出和不支持的格式。Server 已支持 `nativeHttp=true`，原生联调和定位、恢复验收见 [Server 接入设计](server-playback.md)。
2. **接入触屏与系统播放。** 用同一歌单验证手机单栏、平板双栏及分屏切换。旋转时队列和进度连续，锁屏和耳机控件操作同一个播放器。
3. **接入电视。** 在相同应用制品中用电视入口启动，仅用方向键、确认键和返回键完成首次登录、选歌、播放与切歌；从详情返回后焦点回到原项。
4. **接入独立手表。** 手机关机，清除表端应用数据，用手表通过可达的 Wi-Fi 首次登录，在表端选曲并通过耳机播放。验证熄屏、会话过期、短时断网和耳机断开；具备蜂窝能力的设备另测蜂窝直连。此交付范围为独立联网播放，设备矩阵见[交互与验收](device-experiences.md)。
